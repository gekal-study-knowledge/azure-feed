### Summarized Gateway Prefixes for Route Advertisement in Azure Virtual Networks

- **Link**: [https://techcommunity.microsoft.com/t5/azure-networking-blog/summarized-gateway-prefixes-for-route-advertisement-in-azure/ba-p/4521652](https://techcommunity.microsoft.com/t5/azure-networking-blog/summarized-gateway-prefixes-for-route-advertisement-in-azure/ba-p/4521652)

<p><strong>Background</strong></p>
<p>Many Azure deployments follow a <strong>hub-and-spoke topology</strong>: one VNet is designated as the <strong>hub</strong> and holds the connection to on-premises (via ExpressRoute Gateway, VPN Gateway, or both), and workload VNets — the <strong>spokes</strong> — peer to the hub to reach on-premises and shared services. This centralizes gateway connectivity so many workloads can share a single ExpressRoute or VPN Gateway.</p>
<p>However, in large hub-and-spoke topologies, ExpressRoute and VPN Gateway limits on advertised prefixes (for example, 1,000 IPv4 and 100 IPv6 prefixes) can be reached. Because each spoke adds its own address prefixes to that count, these limits are approached quickly, constraining how far the topology can scale.</p>
<p><strong>What's New</strong></p>
<p>With Summarized Gateway Prefixes, customers can now advertise a single covering prefix (for example, 10.0.0.0/16) instead of many smaller CIDRs (for example, multiple /24s) – dramatically reducing advertised route count and enabling larger-scale Azure environments.</p>
<p>A new property, summarizedGatewayPrefixes, is now available on the Virtual Network resource in public preview. When configured on a hub VNet, it controls what your <strong>ExpressRoute Gateway and VPN Gateway</strong> advertise to on-premises, replacing the default behavior of advertising all individual hub and spoke VNet CIDRs with a set of aggregated prefixes you define.</p>
<p>For example, instead of advertising 10.0.1.0/24, 10.0.2.0/24, 10.0.3.0/24, and so on for each spoke, you can advertise a single 10.0.0.0/16.</p>
<p><strong>Key Benefits</strong></p>
<ul>
<li><strong>Fewer advertised routes</strong> — Replace hundreds of individual spoke CIDRs with a small set of summarized prefixes.</li>
<li><strong>Scales with your topology</strong> — Supports deployments with 500+ spokes without requiring address plan redesigns or VNet splits.</li>
<li><strong>IPv4 and IPv6</strong> — Summarize both address families.</li>
<li><strong>Works with both gateway types</strong> — Supported on ExpressRoute Gateway and VPN Gateway.</li>
<li><strong>Simple configuration</strong> — A single property on the VNet resource. No additional services or dependencies.</li>
<li><strong>Backward compatible</strong> — If the property is left empty, behavior is unchanged: all hub and peered spoke address spaces are advertised as before.</li>
</ul>
<p><strong>How It Works</strong></p>
<p><strong>Default behavior</strong></p>
<p>ExpressRoute Gateway and VPN Gateway advertise <strong>all</strong> address spaces of the hub VNet and <strong>all</strong> address spaces of peered spoke VNets to on-premises.</p>
<p><strong>With summarizedGatewayPrefixes configured</strong></p>
<ol>
<li>The gateways advertise <strong>the summarized prefixes</strong> instead of the hub VNet's individual address spaces.</li>
<li>For each peered spoke, if the spoke's address space falls within a summarized prefix, the spoke's individual CIDRs are <strong>suppressed</strong> from advertisement.</li>
</ol>
<ol start="3">
<li>Spoke address spaces <strong>not covered</strong> by a summarized prefix continue to be advertised individually.</li>
</ol>

<p><strong>Getting Started</strong></p>
<ol>
<li>Open the hub VNet (the VNet containing your <strong>GatewaySubnet</strong>) in the Azure portal.</li>
<li>Go to <strong>Address space → Advertised gateway prefixes</strong>.</li>
<li>Add one or more IPv4 or IPv6 CIDR prefixes that cover the address spaces you want to summarize.</li>
</ol>
<p>&nbsp;</p>
<img />
<p>&nbsp;</p>
<ol start="4">
<li>Navigate to your virtual network and verify that the summarized prefixes appear.<br /><img /></li>
</ol>
<p><strong>Things to Know</strong></p>
<ul>
<li>The property is set on the hub VNet (the VNet with the GatewaySubnet).</li>
<li>The summarized prefixes list can include prefixes outside the VNet's own address space.</li>
<li>Avoid overlap among prefixes within the list, but overlap with peered VNet address spaces is expected in hub-and-spoke designs.</li>
<li>For dual-stack (IPv4 + IPv6) VNets, define both IPv4 and IPv6 summarized prefixes explicitly.</li>
</ul>
