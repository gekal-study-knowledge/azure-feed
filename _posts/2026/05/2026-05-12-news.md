<p>Modern enterprises are no longer running workloads only inside a centralized cloud environment. Applications today operate across:</p>
<ul>

<li>Manufacturing plants</li>

<p>While Kubernetes has become the standard for container orchestration, managing Kubernetes consistently across distributed environments introduces operational complexity.</p>
<p>This is where Azure Arc and Azure Kubernetes Service extend the Azure control plane beyond traditional Azure cloud boundaries.</p>
<p>Azure Arc enables organizations to deploy, govern, monitor, and manage Kubernetes clusters running:</p>
<ul>
<li>On-premises</li>
<li>At the edge</li>
<li>In multicloud environments</li>
<li>On virtualization platforms</li>
<li>On physical infrastructure</li>
</ul>
<p>In this guide, we will explore:</p>
<ul>
<li>What Azure Arc AKS is</li>

<li>Networking considerations</li>

<h2>Understanding the Problem Azure Arc Solves</h2>
<p>Traditionally, Kubernetes management becomes fragmented when infrastructure exists outside public cloud environments.</p>
<p>Organizations often face:</p>
<ul>
<li>Separate tooling for on-prem and cloud clusters</li>
<li>Inconsistent governance</li>
<li>Manual onboarding of clusters</li>
<li>Complex identity management</li>
<li>Disconnected monitoring and policy enforcement</li>
<li>Operational overhead at edge locations</li>
</ul>
<p>Azure Arc addresses this by extending Azure management capabilities to infrastructure running anywhere.</p>
<p>Instead of moving all infrastructure into Azure, Azure Arc brings Azure’s operational model to your existing infrastructure.</p>
<h2>What is Azure Arc AKS?</h2>
<p>Azure Arc-enabled Kubernetes allows Kubernetes clusters running outside Azure to become manageable resources inside Azure.</p>
<p>This means:</p>
<ul>
<li>Clusters appear inside Azure Portal</li>
<li>Azure RBAC can be applied</li>
<li>Policies can be enforced centrally</li>
<li>Monitoring and governance become standardized</li>
<li>GitOps and extensions can be deployed consistently</li>
</ul>
<p>AKS Arc extends this further by enabling an AKS-like Kubernetes deployment and lifecycle management experience on local or edge infrastructure.</p>

<h3>Core Components of AKS Arc</h3>
<p>Before deployment, it is important to understand the major components involved.</p>
<h5>1. Azure Arc</h5>
<p>Azure Arc acts as the bridge between Azure and external infrastructure.</p>
<p>It enables:</p>
<ul>
<li>Resource registration</li>
<li>Hybrid governance</li>
<li>Policy enforcement</li>
<li>Monitoring</li>
<li>Extension deployment</li>
<li>Inventory management</li>
</ul>
<h5>2. Arc-Enabled Machines</h5>
<p>These are:</p>
<ul>
<li>Physical servers</li>
<li>Virtual machines</li>
<li>Edge devices</li>
</ul>
<p>Once connected to Azure Arc, they become manageable Azure resources.</p>
<h5>3. Kubernetes Cluster</h5>
<p>The Kubernetes layer provides:</p>
<ul>
<li>Container orchestration</li>
<li>Scheduling</li>
<li>Networking</li>
<li>Scaling</li>
<li>Workload lifecycle management</li>
</ul>
<h5>4. Custom Location</h5>
<p>Custom Locations create a logical mapping between Azure resources and edge infrastructure.</p>
<p>They allow Azure services to target workloads to specific on-prem or edge environments.</p>
<h5>5. Device Pool</h5>
<p>A device pool groups machines participating in a cluster deployment.</p>
<p>This becomes especially important in multi-node environments.</p>
<h5>6. Logical Network (LNET)</h5>
<p>The Logical Network defines:</p>
<ul>
<li>Cluster networking</li>
<li>IP allocation</li>
<li>Gateway configuration</li>
<li>DNS behavior</li>
</ul>
<p>Networking is one of the most critical parts of any AKS Arc deployment.</p>

Login to Azure and Set Subscription

az login
az account set \
  --subscription "&lt;subscription-id&gt;"

Install Connected Machine Agent

#Install Azure Arc agent on Linux machine.
wget https://aka.ms/azcmagent -O ~/install_linux_azcmagent.sh
bash ~/install_linux_azcmagent.sh

Connect Machine to Azure Arc

#Register machine as Arc-enabled server.
sudo azcmagent connect \
  --resource-group "&lt;resource-group&gt;" \
  --tenant-id "&lt;tenant-id&gt;" \
  --location "&lt;azure-region&gt;" \
  --subscription-id "&lt;subscription-id&gt;"

Verify Arc Agent Status

#Confirm successful Arc onboarding.
azcmagent show

Verify Arc Machine in Azure

#List Arc-enabled servers.

  --resource-group "&lt;resource-group&gt;"

<h3>Step 5 – Create the Azure Arc Site</h3>
<p>The Arc Site acts as the logical container for edge infrastructure.</p>
<p>During setup:</p>
<ul>
<li>Select subscription</li>
<li>Choose resource group</li>
<li>Define region</li>
<li>Register machines into the site</li>
</ul>
<p>This enables Azure to organize:</p>
<ul>
<li>Provisioned devices</li>
<li>Clusters</li>
<li>Networking resources</li>
<li>Operational metadata</li>
</ul>
Create Resource Group

#Logical container for Arc resources.
az group create \
  --name "&lt;resource-group&gt;" \
  --location "&lt;azure-region&gt;"


Register Required Providers

#Enable Arc and AKS Arc services.
az provider register --namespace Microsoft.HybridCompute
az provider register --namespace Microsoft.Kubernetes
az provider register --namespace Microsoft.KubernetesConfiguration
az provider register --namespace Microsoft.ExtendedLocation
az provider register --namespace Microsoft.ResourceConnector
az provider register --namespace Microsoft.ContainerService


Verify Provider Registration

#Ensure providers are fully available.
az provider show \
  --namespace Microsoft.Kubernetes \
  --query registrationState


Install Arc Extensions

#Enable AKS Arc management capabilities.
az extension add --name connectedk8s
az extension add --name customlocation
az extension add --name k8s-extension
az extension add --name aksarc


Create Custom Location

#Map Azure services to edge infrastructure.
az customlocation create \
  --name "&lt;custom-location-name&gt;" \
  --resource-group "&lt;resource-group&gt;" \
  --host-resource-id "&lt;connected-cluster-resource-id&gt;" \
  --namespace "&lt;namespace&gt;" \
  --cluster-extension-ids "&lt;extension-id&gt;"

<h3>Understanding Networking Parameters</h3>
<p>Networking is often the most misunderstood area in AKS Arc deployments.</p>
<p>Let us simplify the important parameters.</p>
<h4>Subnet</h4>
<p>Defines the IP range used by:</p>
<ul>
<li>Kubernetes nodes</li>
<li>Cluster services</li>
<li>Internal communication</li>
</ul>
<p>Example:</p>
<blockquote>
<p>192.168.1.0/24</p>
</blockquote>
<h4>DNS Server</h4>
<p>Used for:</p>
<ul>
<li>Name resolution</li>
<li>Azure connectivity</li>
<li>Package downloads</li>
<li>Kubernetes service discovery</li>
</ul>
<p>Public DNS examples:</p>
<blockquote>
<p>8.8.8.8<br />1.1.1.1</p>
</blockquote>
<p>Production environments typically use internal enterprise DNS.</p>
<h4>Default Gateway</h4>
<p>The gateway routes traffic outside the local subnet.</p>
<p>Without correct gateway configuration:</p>
<ul>
<li>Azure connectivity fails</li>
<li>Agent communication breaks</li>
<li>Cluster provisioning may stall</li>
</ul>
<h4>Host IP</h4>
<p>Each machine requires a unique static IP.</p>
<p>This IP identifies:</p>
<ul>
<li>Kubernetes nodes</li>
<li>Cluster hosts</li>
<li>Edge infrastructure endpoints</li>
</ul>
<h4>Control Plane IP</h4>
<p>The Kubernetes API server requires a stable endpoint.</p>
<p>This becomes the cluster management address used by:</p>
<ul>
<li>kubectl</li>
<li>automation tools</li>
<li>CI/CD systems</li>
</ul>

<h2>Common Challenges in AKS Arc Deployments</h2>
<p>Real-world deployments are rarely frictionless.</p>

<h3>1. Networking Misconfiguration</h3>

<ul>
<li>Provisioning stuck</li>
<li>Cluster not connecting</li>
<li>Agents unhealthy</li>

<p>Root causes:</p>
<ul>
<li>Incorrect subnet</li>
<li>Invalid gateway</li>
<li>DNS failures</li>
<li>Firewall restrictions</li>
</ul>
<h3>2. Slow Provisioning</h3>
<p>Provisioning delays are common.</p>
<p>Reasons include:</p>
<ul>
<li>Extension deployment time</li>
<li>Image downloads</li>
<li>Edge connectivity latency</li>
<li>Infrastructure initialization</li>
</ul>
<p>Patience becomes important during initial deployment.</p>
<h3>3. Resource Constraints</h3>
<p>Insufficient:</p>
<ul>
<li>RAM</li>
<li>CPU</li>
<li>Storage</li>
</ul>
<p>can destabilize the Kubernetes environment.</p>
<p>Edge clusters still require enterprise-grade resource planning.</p>
<h3>4. Hybrid Debugging Complexity</h3>
<p>Troubleshooting spans:</p>
<ul>
<li>Azure</li>

<li>Networking</li>
