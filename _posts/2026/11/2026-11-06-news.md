### Azure DNS Traffic Manager linked records are now generally available

- **Link**: [https://techcommunity.microsoft.com/t5/azure-networking-blog/azure-dns-traffic-manager-linked-records-are-now-generally/ba-p/4547112](https://techcommunity.microsoft.com/t5/azure-networking-blog/azure-dns-traffic-manager-linked-records-are-now-generally/ba-p/4547112)
- **Published**: 2026-11-06 01:42:14
- **Fetched**: 2026-11-06 05:51:34

<details class="entry-summary">
<summary>詳細を表示</summary>
<p>We're excited to announce the <strong>general availability of Azure Traffic Manager linked records</strong>, a new Azure DNS capability that enables customers to directly associate Azure Public DNS record sets with Azure Traffic Manager profiles without using a CNAME to trafficmanager.net.</p>
<p>With this capability, customers can use Traffic Manager's DNS-based load balancing capabilities without exposing the intermediate trafficmanager.net domain in DNS responses. Azure DNS and Traffic Manager now work together to provide a more seamless, integrated DNS experience for applications running across Azure, hybrid, and multi-cloud environments.</p>
<h3>Simplifying DNS-based traffic routing</h3>
<p>Traditionally, customers using Azure DNS with Traffic Manager relied on CNAME records that returned a Traffic Manager hostname. DNS clients would then perform an additional lookup to resolve that hostname before reaching the application endpoint.</p>
<p>Traffic Manager linked records<strong> </strong>simplifies this process by allowing Azure DNS to resolve Traffic Manager routing decisions internally and return the appropriate endpoint information directly to clients.</p>
<p>The result is a cleaner DNS resolution path while preserving all of Traffic Manager's existing routing methods, health monitoring, and failover capabilities.</p>
<img />
<h3>Key benefits</h3>
<p><strong>Better integration between Azure DNS and Azure Traffic Manager</strong></p>
<p>Traffic Manager linked records allow Azure DNS record sets to directly reference Traffic Manager profiles, including nested profile configurations.</p>
<p>This enables sophisticated traffic routing architectures without relying on intermediate CNAME records, making complex global deployments easier to build and manage.</p>
<p><strong>Improved security and DNS hygiene</strong></p>
<p>Because DNS responses no longer expose the intermediate <strong>trafficmanager.net</strong> domain, organizations can simplify firewall rules and reduce reliance on intermediate DNS names.</p>
<p>Traffic Manager linked records also help eliminate a common source of dangling subdomains caused by orphaned or misconfigured <strong>trafficmanager.net</strong> records, strengthening overall DNS hygiene and reducing operational risk.</p>
<p><strong>DNSSEC for Traffic Manager</strong></p>
<p>Traffic Manager routing decisions are now resolved within Azure DNS, If the DNS zone is a DNSSEC signed zone the answers supplied by linked Traffic Manager&nbsp;profiles are automatically signed as well. This enables customer to use Traffic Manager profiles with DNSSEC, unlike a CNAME to trafficmanager.net which would break the DNSSEC end to end validation chain as trafficmanager.net is not a signed zone.</p>
<p><strong>Zone apex load balancing</strong></p>
<p>Traffic Manager Linked Records enable DNS-based load balancing directly at the <strong>zone apex</strong> (for example, <strong>contoso.com</strong>), where traditional CNAME records are prohibited by DNS standards. Customers can now bring Traffic Manager routing to root domains without complex workarounds. This is similar to ALIAS records but with much better integration and scale.</p>
<p><strong>Cleaner &amp; faster DNS responses</strong></p>
<p>Clients now receive the final endpoint directly from Azure DNS instead of first resolving a <strong>trafficmanager.net</strong> hostname. By removing an extra DNS lookup, applications can experience lower DNS resolution latency while benefiting from Traffic Manager's intelligent routing decisions.</p>
<p><strong>Built-in operational safeguards with strictly typed profiles</strong></p>
<p>Traffic Manager linked records integrate with <strong>strictly typed profiles </strong>in Azure Traffic Manager, providing validation that helps ensure DNS record types remain compatible with their associated Traffic Manager profiles. In simpler words, this feature ensures that type of response served by the traffic manager profile matches the type of DNS records it is linked to.</p>
<p>The feature also prevents accidental deletion of Traffic Manager profiles that are still referenced by Azure DNS records, reducing the risk of configuration errors and improving operational safety.</p>
<h3>Getting started</h3>
<p>Traffic Manager linked records are <strong>generally available</strong> today.</p>
<p>Following record types can be used with Traffic Manager Linked Records</p>
<ul>
<li><strong>A </strong></li>
<li><strong>AAAA </strong></li>
<li><strong>CNAME </strong></li>
</ul>
<p>Traffic Manager linked records are designed to make DNS-based load balancing simpler, faster, and more secure while preserving the flexibility and reliability customers expect from Azure Traffic Manager.</p>
<p>To learn more and start using Traffic Manager linked records today, see the <a class="lia-external-url" href="https://learn.microsoft.com/azure/dns/dns-traffic-manager-linked-records" rel="noopener" target="_blank">DNS Traffic Management</a> documentation.</p>
