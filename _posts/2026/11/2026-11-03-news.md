<h2>The question after the cost chart</h2>
<p>The monthly cost review usually starts with a straightforward observation: Azure spending changed.</p>
<p>Then come the questions that take the time.</p>
<p>Which subscription accounts for the increase? Is it an existing workload getting more expensive, or something that only started generating charges this month? Did a reduction somewhere else hide part of the increase? And which optimization recommendations are worth taking to a workload owner?</p>
<p>Azure already has the underlying information. Cost Management provides spending data. Azure Advisor provides optimization recommendations. Resource inventory provides context about what those resources are.</p>
<p>The work is connecting those sources into an explanation that someone can check and act on.</p>
<p><strong>Conversational Cost Analytics Agent: </strong>a solution built around Azure SRE Agent that lets operations and FinOps leads start with a question, investigate cost drivers, identify optimization opportunities, and generate reusable reports. The solution can also generate proactive alerts and scheduled reports.</p>
<p><strong>Scope of this post:</strong> The repository contains a prototype, an importable dashboard template, reusable skills, and example report screenshots. These demonstrate the reporting approach; they are not evidence of measured customer savings, verified production readiness, or a completed deployment in your environment. The prompts below are examples to try, not a transcript of a measured production investigation.</p>
<h2>What we built</h2>
<p>This is a custom cost-investigation workflow on Azure SRE Agent, not a separate billing system or a claim that every feature is available out of the box.</p>
<p>The solution brings together three pieces:</p>
<ul>
<li><strong>An analytical skill</strong> that describes how to compare spending, calculate resource contributions, identify newly billed resources, and handle incomplete periods.</li>
<li><strong>A query-reference skill</strong> that records the Cost Management query patterns, response shapes, aggregation rules, and SRE Agent tool mappings used by the dashboard workflow.</li>
<li><strong>An HTML Live Report template</strong> that presents subscription selection, summary metrics, six-month trends, and expandable resource-level comparisons.</li>
</ul>
<p>The distinction matters. A template determines how findings appear. A skill determines how the agent should investigate. Neither replaces access to the underlying data.</p>
<p>The agent still needs scoped permissions, supported tools, and a successful data refresh before the report can represent your subscriptions.'</p>
<h2>How the investigation works</h2>
<p>The workflow starts by discovering the subscriptions the agent can access. It then queries Cost Management for historical totals and current- and previous-month resource-level details, aggregates the results, and populates the report template.</p>
<div class="styles_lia-table-wrapper__h6Xo9 styles_table-responsive__MW0lN"><table border="1" style="width: 85.0926%; height: 210px; border-width: 1px;"><colgroup><col style="width: 24.8378%;" /><col style="width: 75.1622%;" /></colgroup><tbody><tr style="height: 35px;"><td style="height: 35px;"><strong>Source or component</strong></td><td style="height: 35px;"><strong>Role in the investigation</strong></td></tr><tr style="height: 35px;"><td style="height: 35px;">Azure Cost Management</td><td style="height: 35px;">Billing-based cost data and historical comparisons</td></tr><tr style="height: 35px;"><td style="height: 35px;">Azure Resource Graph</td><td style="height: 35px;">Resource inventory and metadata enrichment, not cost data</td></tr><tr style="height: 35px;"><td style="height: 35px;">Azure Advisor</td><td style="height: 35px;">Optimization recommendations to review alongside spending</td></tr><tr style="height: 35px;"><td style="height: 35px;">Reusable agent skills</td><td style="height: 35px;">Investigation rules, query patterns, and interpretation guardrails</td></tr><tr style="height: 35px;"><td style="height: 35px;">Live Report template</td><td style="height: 35px;">Interactive presentation of the refreshed data snapshot</td></tr></tbody></table>
<p>&nbsp;</p>
</div>
<ul>
<li><strong>How cost data is collected:</strong> The agent sends a request to Azure Cost Management to retrieve spending data. The request uses HTTP POST, so the kit runs it through RunAzCliWriteCommands, even though it only reads data.</li>
<li><strong>Reading costs does not change resources:</strong> This query does not resize, delete, or modify resources. Still, configure permissions and tools carefully to limit what the agent can do.</li>
<li><strong>The report shows the most recently refreshed data:</strong> Opening the report displays the data collected during its most recent refresh. It does not automatically request updated billing data.</li>
<li><strong>Fetching data directly from the report requires a connector:</strong> A supported connector gives the report access to a cost-query tool. The report cannot directly use the agent’s built-in CLI tools.</li>
<li><strong>You can start without a connector:</strong> Use the report with periodically refreshed data, and add a connector later if you need to fetch updates directly from the report.</li>
</ul>
<h2>Four questions to explore in the report</h2>
<h3>1. Where is spending heading?</h3>
<p>Start with the broad view:</p>
<p>The overview brings subscription selection, summary KPIs, previous-month actuals, and an adjustable cost trend into one view. Select the number of months you want to compare, up to 12, and expand any month to explore the services behind the spending changes.</p>
<img />
<p><em>Figure 1. Historical prototype snapshot, not current pricing or a verified financial result. The current-month KPI is a projection; the screenshot does not establish that the partial-month trend bar uses the same basis. Reconcile those values and use consistent labels before relying on the comparison.</em></p>
<p>This is also where an apparently simple comparison can become misleading. Ten days of current-month spend and a full previous month are not comparable periods.</p>
<p>For an in-progress month, ask for matched month-to-date periods when investigating change. If the report displays a full-month run-rate projection, keep it labeled as a projection. Do not describe it as a Cost Management forecast unless that forecast was actually retrieved.</p>
<p>The useful outcome is not just a larger or smaller bar. It is an explicit statement of the period, cost basis, currency, and freshness behind that bar.</p>
<h3>2. Which resources explain the change?</h3>
<p>Once the subscription-level movement is clear, move to the contributors:</p>
<p class="lia-indent-padding-left-30px"><em>"Rank the resources driving increases and decreases. Separate newly billed resources from existing resources whose costs changed."</em></p>
<p>The resource view compares spending at the resource level, highlights resources appearing in the current period’s billing data, and supports expandable service breakdowns.</p>
<img />
<p><em>Figure 2. Historical prototype comparison. The screenshot's "New Resources" label means newly observed in billing, not confirmed creation. In this example workflow, current-month "Full" values are projections, not completed-month actuals.</em></p>
<p>The agent can help break down cost changes that might otherwise require multiple spreadsheets and time-consuming manual comparisons:</p>
<ul>
<li><strong>New charges do not always mean new resources:</strong>&nbsp;An existing resource may start generating charges after a period of inactivity. Costs may also rise because of autoscaling, longer VM running hours, increased storage usage, more read/write operations, or billable data transfers. These changes can be difficult to spot in summary reports.</li>
<li><strong>Newly created resources can add to spending:</strong>&nbsp;The agent can highlight resources appearing in the current period’s billing data. Resource inventory or deployment history is needed to confirm whether they were newly created or simply started generating charges.</li>
<li><strong>One resource can have several cost entries:</strong>&nbsp;A resource may appear in multiple billing records for different services or meters. Adding the relevant entries together helps show its total cost and contribution to the change.</li>
<li><strong>The net change can hide larger movements:</strong>&nbsp;For example, if one resource’s cost increases by $800 while another decreases by $300 over comparable periods, the net increase is $500. Showing both changes reveals the increase and the offsetting reduction. These figures are illustrative.</li>
<li><strong>Finding the cost driver is not the same as finding the cause:</strong> Identifying which resource contributed to an increase is the first step. Explaining why it happened may require additional evidence about usage, configuration changes, pricing, or other factors.</li>
</ul>
<h3>3. Which optimization opportunities deserve attention?</h3>
<p>The next question is usually practical:</p>
<p class="lia-align-center"><em>"Show Azure Advisor cost optimization recommendations for the subscriptions in scope. Separate estimated savings from confirmed spending reductions."</em></p>
<p>The repository includes an example Advisor optimization view for reviewing rightsizing and commitment-related opportunities alongside the cost investigation.</p>
<img />
<p><em>Figure 3. Historical prototype optimization view. Displayed savings are estimates, not realized savings; low CPU alone does not establish that shutdown is appropriate. A displayed zero for reservations requires a successful, authorized query before it can be interpreted as no reservations.</em></p>
<p>The useful next step is to review the findings with the workload owner, not to make an automatic purchase or resize a resource.</p>
<p>Rightsizing can change the baseline for a reservation or savings plan decision. Recommendations can also overlap, so adding every displayed savings figure may overstate the opportunity. Billing and commitment visibility depend on the identity's actual access; subscription resource access does not automatically expose every reservation or savings plan dataset.</p>
<p>An unavailable dataset should be reported as unavailable. It should never silently become "no recommendations" or "no commitments."</p>
<h3>4. What might we be paying for without using?</h3>
<p>Finally, investigate cleanup candidates:</p>
<p class="lia-indent-padding-left-30px"><em>"Identify potentially orphaned resources and show the evidence that makes each one a candidate for owner review."</em></p>
<p>The example orphaned-resource view covers candidates such as unattached disks, stale snapshots, unassociated public IP addresses and network interfaces, and empty App Service plans.</p>
<img />
<p><em>Figure 4. Example cleanup-candidate inventory. An apparent orphan is an investigation finding, not deletion approval.</em></p>
<p>An unattached disk may be retained for recovery. A snapshot may be subject to a retention requirement. A network resource may be reserved for a planned deployment.</p>
<p>The report should help the owner answer those questions by identifying the resource, its state, and any observed charges. It should not turn "not currently attached" into "safe to delete."</p>
<p>The intended configuration is read-only reporting and investigation. Validate the identity's effective permissions and enabled tools before use; the template alone does not enforce that boundary. Any cleanup requires separate validation and explicit approval.</p>
<h2>Have a meaningful cost conversation with the agent</h2>
<p>A cost dashboard remains useful. It shows the shape of spending and gives people a shared view. However, a conversational approach takes this further by helping users investigate what is driving spending, identify key contributors, distinguish new charges from changes in existing resources, and explore cost optimization opportunities.</p>
<p>Start with a simple cost question, then use follow-up prompts to explore what changed, which resources contributed, and what needs further investigation.</p>
<p><strong>Example prompts include:</strong></p>
<p class="lia-indent-padding-left-30px">“Which subscriptions and resources explain the largest cost increases compared with last month?”</p>
<p class="lia-indent-padding-left-30px">“Why did costs increase this month?”</p>
<p class="lia-indent-padding-left-30px">“Which resources contributed most to the increase?”</p>
<p class="lia-indent-padding-left-30px">“Is this newly billed spending or higher costs from existing resources?”</p>
<p class="lia-indent-padding-left-30px">“Compare the last three months and show the biggest changes.”</p>
<p class="lia-indent-padding-left-30px">“Create a report focused on this subscription and its top cost drivers.”</p>
<p class="lia-indent-padding-left-30px">“Show Azure Advisor savings opportunities and orphaned resources that require owner review.”</p>
<p class="lia-indent-padding-left-30px">“Refresh this report every Monday morning.”</p>
<p>With the required data access and tools configured, the agent can help rerun analyses, narrow the scope, and generate reports focused on specific cost questions. Scheduled reports and cost alerts require supported capabilities, appropriate permissions, and separate configuration. Check findings against source data before making decisions or changing resources.</p>
<h2>Try it in your environment</h2>
<p>Start with one subscription whose costs you already understand. That makes it easier to reconcile the first report before expanding the scope.</p>

<li><strong>Add the three skills</strong> from the <a href="https://github.com/Asithdee/Azure/blob/main/SREAgent/ConversationalCostAnalyticsAgent/skills" rel="noopener" target="_blank">skills folder</a>, and upload the <a href="https://github.com/Asithdee/Azure/blob/main/SREAgent/ConversationalCostAnalyticsAgent/knowledge/cost-analysis-playbook.md" rel="noopener" target="_blank">cost analysis playbook</a> as a knowledge source.</li>

<li><strong>Bootstrap the report.</strong> Submit the first-run prompt from the <a href="https://github.com/Asithdee/Azure/tree/main/SREAgent/ConversationalCostAnalyticsAgent/prompts" rel="noopener" target="_blank">bootstrap prompts</a> and provide the <a href="https://github.com/Asithdee/Azure/tree/main/SREAgent/ConversationalCostAnalyticsAgent/reports" rel="noopener" target="_blank">HTML report template</a>.</li>
