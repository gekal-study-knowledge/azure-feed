<p>Today, we’re excited to announce the general availability of the <a href="https://learn.microsoft.com/en-us/agent-framework/hosting/azure-functions?tabs=bash&amp;pivots=programming-language-csharp" rel="noopener" target="_blank">Durable Task extension for Microsoft Agent Framework</a>. It brings the reliable execution model of <a href="https://learn.microsoft.com/en-us/azure/durable-task/scheduler/durable-task-scheduler" rel="noopener" target="_blank">Durable Task</a> to <a href="https://learn.microsoft.com/en-us/agent-framework/" rel="noopener" target="_blank">Agent Framework</a>, helping agents and agentic workflows recover from failures and interruptions without losing their progress.</p>
<p>Saving a conversation is only part of the story. When an agent is doing work, your application also needs to know which steps have finished, which jobs are still running, and whether it’s waiting for someone’s approval. If the application restarts, that information makes the difference between continuing the work and figuring out where to begin again.</p>
<p>The Durable Task extension keeps track of that state for you. Agents can continue the same conversation after a worker restart, and workflows can pick up interrupted work without repeating steps whose results have already been saved. They can also wait for approvals or external events without keeping a worker running. You can focus on what your agents do, with less state management and recovery code to build yourself.</p>
<p>Run durable agents and workflows in <a href="https://learn.microsoft.com/azure/azure-functions/functions-overview" rel="noopener" target="_blank">Azure Functions</a>, or self-host them in your own .NET or Python application.</p>
<h2>Key capabilities of the Durable Task extension</h2>
<p>The Durable Task extension adds two capabilities to <a href="https://learn.microsoft.com/agent-framework/" rel="noopener" target="_blank">Microsoft Agent Framework</a> that work together: durable agents and durable workflows.</p>
<p><strong>Durable agents</strong> keep conversation and session state between requests. Each agent call runs through Durable Task, so saved session state stays available even if a worker restarts or another application instance handles the next request. The conversation can continue without relying on the original process.</p>
<p><strong>Durable workflows</strong> keep track of work that takes multiple steps or runs over time. You can write <a href="https://learn.microsoft.com/azure/durable-task/sdks/durable-task-overview" rel="noopener" target="_blank">Durable Task orchestrations</a> to coordinate agent calls, application activities, and external events. If you prefer <a href="https://learn.microsoft.com/agent-framework/workflows/" rel="noopener" target="_blank">Agent Framework’s graph-based workflows</a>, the extension runs those graphs as Durable Task orchestrations and handles registration of their agents and executors.</p>
<p>The two come together when an interactive agent needs to start work that won’t finish in a single request. The agent can launch a workflow and return its instance ID rather than keep the user waiting. The workflow continues independently, including waiting for results or approvals. The agent can use that ID later to check progress or send an event, such as an approval decision.</p>
<p>The examples below show how this works in practice: continuing a conversation, coordinating work across multiple steps, waiting for someone’s input, and managing session state and model context. Later in the post, we’ll show how to set up the host that runs these examples.</p>
<h3>Agent sessions that survive interruptions</h3>
<p>Suppose a customer starts a support conversation, then comes back with their order number. In between, your application restarts or another worker takes over. The agent should be able to pick up the conversation where it left off.</p>
<p>Agent Framework can keep sessions in memory or use a persistent history provider to save messages between requests. A durable agent builds on that with a managed path for running agent calls and restoring session state, so you don’t have to wire that together yourself.</p>
<p>With the Durable Task extension, each conversation has a stable durable session ID, and saved session state lives outside the worker process. Your application keeps the session reference. When the customer returns, another compatible worker can use that reference to continue the same conversation.</p>
<p>The examples below show two separate requests. The first starts the conversation and serializes its session reference, which your application must save for later use. Serialization alone does not save it. The later request loads that reference and reconnects to the same durable session, without needing the original session object. Both requests use the same Durable Task backend, with SupportAgent registered through the extension.&nbsp;</p>
<h4>C#</h4>
using System.Text.Json;
using Microsoft.Agents.AI;
using Microsoft.Agents.AI.DurableTask;

// First request: start the conversation and return its session object.
static async Task&lt;JsonElement&gt; StartConversationAsync(
    IServiceProvider services)
{
    AIAgent agent = services.GetDurableAgentProxy("SupportAgent");
    AgentSession session = await agent.CreateSessionAsync();

    await agent.RunAsync(
        "I need help with my order.",
        session: session);

    // SerializeSessionAsync returns only the lightweight JSON session reference
    // (containing the durable session ID); Durable Task already stores the
    // conversation history in the backend.
    return await agent.SerializeSessionAsync(session);
}

// Later request, after a restart or on another compatible worker.
// Load savedSession from your application's durable storage before calling.
static async Task&lt;AgentResponse&gt; ContinueConversationAsync(
    IServiceProvider services,
    JsonElement savedSession)
{
    AIAgent agent = services.GetDurableAgentProxy("SupportAgent");
    AgentSession session = await agent.DeserializeSessionAsync(savedSession);

    return await agent.RunAsync(
        "The order number is 12345.",
        session: session);
}
<h4>Python</h4>
from typing import Any

from agent_framework import AgentResponse
from agent_framework_durabletask import (
    DurableAIAgentClient,
    DurableAgentSession,
)


# First request: start the conversation and return its serialized session reference.
def start_conversation(
    durable_client: DurableAIAgentClient,
) -&gt; dict[str, Any]:
    agent = durable_client.get_agent("SupportAgent")
    session = agent.create_session()

    agent.run("I need help with my order.", session=session)

    # to_dict() returns only the lightweight session reference dict (containing
    # durable_session_id); Durable Task already stores the conversation history
    # in the backend.
    return session.to_dict()


# Later request, after a restart or on another compatible worker.
def continue_conversation(
    durable_client: DurableAIAgentClient,
    saved_session: dict[str, Any],
) -&gt; AgentResponse:
    agent = durable_client.get_agent("SupportAgent")
    session = DurableAgentSession.from_dict(saved_session)

    return agent.run("The order number is 12345.", session=session)
<h3>Coordinate multi-step agentic workflows reliably</h3>
<p>A simple customer question can lead to several steps: look up records, prepare a response, and send it to the right person or system. If something interrupts the process halfway through, your application needs to know what has already finished and what still needs to happen.</p>
<p>Durable Task saves the results of agent calls and activities as the workflow progresses. After an interruption, the orchestration replays its history, reuses saved results, and continues with unfinished work. Completed agent calls whose results have been recorded don’t need to call the model again during replay, avoiding unnecessary token usage and inference costs during recovery.</p>
<h4>C#</h4>
// Registered as the Durable Task orchestration for this workflow.
static async Task&lt;string&gt; RunOrderResponseWorkflowAsync(
    TaskOrchestrationContext context,
    string orderNumber)
{
    DurableAIAgent agent = context.GetAgent("OrderAgent");
    AgentSession session = await agent.CreateSessionAsync();

    AgentResponse&lt;TextResponse&gt; summary = await agent.RunAsync&lt;TextResponse&gt;(
        message: $"Summarize order {orderNumber}.",
        session: session);

    AgentResponse&lt;TextResponse&gt; reply = await agent.RunAsync&lt;TextResponse&gt;(
        message: $"Draft a customer reply: {summary.Result.Text}",
        session: session);

    return reply.Text;
}
<h4>Python</h4>
# Registered as the Durable Task orchestration for this workflow.
def run_order_response_workflow(
    context: OrchestrationContext,
    order_number: str,
):
    agent_context = DurableAIAgentOrchestrationContext(context)
    agent = agent_context.get_agent("OrderAgent")
    session = agent.create_session()

    summary = yield agent.run(
        messages=f"Summarize order {order_number}.",
        session=session,
    )

    reply = yield agent.run(
        messages=f"Draft a customer reply: {summary.text}",
        session=session,
    )

    return reply.text
<h3>Make graph-based workflows durable</h3>
<p>If you prefer to build workflows as graphs in Agent Framework, you can use that approach too. The Durable Task extension runs your graph as a durable orchestration, keeping track of its progress so it can recover from failures and interruptions.</p>
<p>You only need to register the graph. The extension takes care of registering its agents, activities for the other executors, and the orchestration that runs it.</p>
<h4>C#</h4>
Workflow expertTeamWorkflow = new WorkflowBuilder(questionParser)
    .WithName("ExpertTeamReview")
    .AddFanOutEdge(questionParser, [biologist, physicist])
    .AddFanInBarrierEdge([biologist, physicist], responseAggregator)
    .Build();

services.ConfigureDurableWorkflows(
    options =&gt; options.AddWorkflow(expertTeamWorkflow));
<h4>Python</h4>
expert_team_workflow = (
    WorkflowBuilder(
        name="ExpertTeamReview",
        start_executor=question_parser,
    )
    .add_fan_out_edges(
        source=question_parser,
        targets=[biologist, physicist],
    )
    .add_fan_in_edges(
        sources=[biologist, physicist],
        target=response_aggregator,
    )
    .build()
)

# agent_worker wraps the Durable Task worker.
agent_worker.configure_workflow(expert_team_workflow)
<p>As agents and executors finish their work, Durable Task saves their results and reuses them during replay. You define how the work connects in the graph, and Durable Task handles preserving progress and recovering execution.</p>
<h3>Human in the loop</h3>
<p>Sometimes an agent needs someone to review a draft, approve an action, or provide more information before the work can continue. That response might take an hour, a day, or longer. Keeping a worker running just to wait can add cost and prevent the application from scaling down.</p>
<p>With the Durable Task extension, the workflow can save its progress and wait for an external event without keeping a worker active. When the person responds, an HTTP endpoint, agent tool, or other application code sends the event to the matching workflow instance. The orchestration picks up from its saved state and continues the work.</p>
<h4>C#</h4>
// Registered as the Durable Task orchestration for this workflow.
static async Task&lt;string&gt; RunContentReviewWorkflowAsync(
    TaskOrchestrationContext context,
    GeneratedContent draft)
{
    await context.CallActivityAsync(nameof(NotifyReviewer), draft);

    HumanApprovalResponse decision = await context.WaitForExternalEvent&lt;HumanApprovalResponse&gt;(
        eventName: "HumanApproval",
        timeout: TimeSpan.FromHours(24));

    if (!decision.Approved)
        return "Content was not approved.";

    await context.CallActivityAsync(nameof(PublishContent), draft);

    return "Content published.";
}

// From the approval endpoint or agent tool, outside the orchestration:
await client.RaiseEventAsync(instanceId, "HumanApproval", approvalResponse);
<h4>Python</h4>
# Registered as the Durable Task orchestration for this workflow.
def run_content_review_workflow(
    context: OrchestrationContext,
    draft: dict[str, str],
):
    yield context.call_activity("notify_reviewer", input=draft)

    decision = yield context.wait_for_external_event("HumanApproval")

    if not decision["approved"]:
        return {"status": "not-approved"}

    yield context.call_activity("publish_content", input=draft)

    return {"status": "published"}

# From the approval endpoint or agent tool, outside the orchestration:
client.raise_orchestration_event(
    instance_id=instance_id,
    event_name="HumanApproval",
    data={"approved": True},
)

<h3>Azure Functions</h3>
<p>Azure Functions gives you managed HTTP endpoints and scales with demand. To get started, add Microsoft.Agents.AI.Hosting.AzureFunctions for .NET or agent-framework-azurefunctions for Python to your Functions project, and configure its Durable Task backend.</p>
<h4><span style="color: rgb(30, 30, 30); font-size: 28px;">C# example for Azure Functions</span></h4>
<p>Register standalone agents and agents used by your own orchestrations with ConfigureDurableAgents. For Agent Framework workflow graphs, use ConfigureDurableWorkflows. You can use either method on its own or combine them to host agents and graphs in the same application.</p>
using IHost app = FunctionsApplication
    .CreateBuilder(args)
    .ConfigureFunctionsWebApplication()
    .ConfigureDurableAgents(options =&gt; options.AddAIAgent(agent))
    .ConfigureDurableWorkflows(options =&gt; options.AddWorkflow(workflow))
    .Build();

app.Run();
<p>For a Durable Task orchestration, mark its entry point with [Function] and [OrchestrationTrigger] so Azure Functions can discover it. If you register an Agent Framework graph, the extension creates the supporting orchestration for you.</p>
<h4>Python</h4>
<p>Pass standalone agents and agents used by your own orchestrations to AgentFunctionApp through the agents argument. For an Agent Framework graph, use the workflow argument. You can provide either or both.</p>
from agent_framework_azurefunctions import AgentFunctionApp

app = AgentFunctionApp(
    agents=[agent],
    workflow=workflow,
)
<p>For a Durable Task orchestration, mark its entry point with <a class="lia-mention lia-mention-user" href="">app​</a>.orchestration_trigger(context_name="context"). For an Agent Framework graph, AgentFunctionApp adds that trigger for you.</p>
<p>The <a href="https://github.com/microsoft/agent-framework-durable-extension/tree/main/dotnet/samples/DurableAgents/AzureFunctions" rel="noopener" target="_blank">C# Functions samples</a> and <a href="https://github.com/microsoft/agent-framework-durable-extension/tree/main/python/samples/azure_functions" rel="noopener" target="_blank">Python Functions samples</a> show the full project setup and how to call your agents and workflows.</p>
<h3>Self-hosted applications</h3>
<p>You can also run durable agents and workflows in your own application with Microsoft.Agents.AI.DurableTask for .NET or agent-framework-durabletask for Python. You choose where the application runs and how users or other systems call it. Durable Task handles saving execution state and recovering work after interruptions.</p>
<h4>C# example for self-hosted applications</h4>
<p>Configure the Durable Task worker and client, register your agents, and add any Agent Framework graphs.</p>
using IHost host = Host.CreateDefaultBuilder(args)
    .ConfigureServices(services =&gt;
    {
        services.ConfigureDurableAgents(
            options =&gt; options.AddAIAgent(agent),
            workerBuilder: builder =&gt; builder.UseDurableTaskScheduler(connectionString),
            clientBuilder: builder =&gt; builder.UseDurableTaskScheduler(connectionString));

        services.ConfigureDurableWorkflows(
            options =&gt; options.AddWorkflow(workflow));
    })
    .Build();

await host.RunAsync();
<p>For a Durable Task orchestration, also register it through AddTasks in the workerBuilder callback. For example, this registers the earlier order-response function and passes it the orchestration input:</p>
workerBuilder: builder =&gt;
{
    builder.UseDurableTaskScheduler(connectionString);

    builder.AddTasks(registry =&gt; registry.AddOrchestratorFunc(
        "RunOrderResponseWorkflow",
        (TaskOrchestrationContext context) =&gt; RunOrderResponseWorkflowAsync(
            context,
            context.GetInput&lt;string&gt;() ?? throw new ArgumentException(
                "An order number is required."))));
}
<p>The scheduler integration requires Microsoft.DurableTask.Worker.AzureManaged and Microsoft.DurableTask.Client.AzureManaged alongside the extension.</p>
<h4>Python example for self-hosted applications</h4>
<p>Pass your configured Durable Task worker to DurableAIAgentWorker, then register your agents, orchestrations, and workflow graphs before starting the worker.</p>
from agent_framework_durabletask import DurableAIAgentWorker

agent_worker = DurableAIAgentWorker(worker)

# Register an agent and an orchestration you wrote directly.
agent_worker.add_agent(order_agent)
worker.add_orchestrator(run_order_response_workflow)

# Register a graph and let the extension configure its components.
agent_worker.configure_workflow(workflow)

worker.start()
<p>Register only the components your application needs, or combine them in the same worker. Your application keeps the worker running and calls worker.stop() when it shuts down.</p>
