## Azure Networking Blog

### Proactively monitor Azure VPN Gateway tunnel disconnections

- **Link**: [https://techcommunity.microsoft.com/t5/azure-networking-blog/proactively-monitor-azure-vpn-gateway-tunnel-disconnections/ba-p/4562011](https://techcommunity.microsoft.com/t5/azure-networking-blog/proactively-monitor-azure-vpn-gateway-tunnel-disconnections/ba-p/4562011)
- **Published**: 2026-10-07 01:47:21
- **Fetched**: 2026-10-07 18:29:29

<details class="entry-summary">
<summary>詳細を表示</summary>
<p>Site-to-Site (S2S) VPN connections are a critical component of hybrid connectivity between Azure and on-premises environments. A tunnel outage can impact applications, user access, and business operations. Although Azure VPN Gateway automatically attempts to re-establish a tunnel when connectivity is restored, administrators should be notified immediately when a tunnel disconnects so they can quickly investigate and mitigate the issue.</p>
<p>In this article, you'll learn how to configure an Azure Monitor alert that automatically notifies administrators whenever an Azure VPN Gateway tunnel enters a disconnected state.</p>
<p><strong>Why monitor VPN tunnel status?</strong></p>
<p>VPN tunnels can disconnect for a variety of reasons, including:</p>
<ul>
<li>Internet connectivity issues</li>
<li>On-premises VPN device failures</li>
<li>IPSec/IKE negotiation issues</li>
<li>Network maintenance activities</li>
<li>Device reboots or software upgrades</li>
</ul>
<p>By implementing proactive monitoring, organizations can:</p>
<ul>
<li>Reduce Mean Time to Detection (MTTD)</li>
<li>Improve network availability</li>
<li>Receive automated notifications</li>
</ul>
<p>&nbsp;</p>
<p><strong>Step 1: Enable VPN Gateway diagnostic logs</strong></p>
<p>Before creating an alert rule, ensure that diagnostic logging is enabled for your VPN Gateway.</p>
<ol>
<li>Navigate to Azure Monitor in the Azure portal.</li>
<li>Under Settings, select Diagnostic settings.</li>
<li>Select the appropriate Subscription, Resource Group, and Resource Type, then choose your VPN Gateway resource.</li>
<li>Click Add diagnostic setting.</li>
<li>Provide a name for the diagnostic setting and select AllLogs (or at minimum TunnelDiagnosticLog).</li>
<li>Choose Send to Log Analytics Workspace (or Event Hub / Storage Account, as required).</li>
<li>Click Save to apply the diagnostic setting.</li>
</ol>
<p>&nbsp;</p>
<p><strong>Step 2: Create an alert rule</strong></p>
<p>&nbsp;</p>
<p>After enabling diagnostics, navigate to Azure Portal &gt; Monitor &gt; Alerts, and select Create &gt; Alert Rule.</p>
<p><strong>Scope</strong></p>
<p>Select Scope and click Select scope. In the resource selection pane, choose your Virtual Network Gateway (VPN Gateway) resource and click Apply. This sets the VPN Gateway as the target resource for the alert rule.</p>
<p>&nbsp;</p>
<img />
<p>&nbsp;</p>
<p>&nbsp;</p>
<p><strong>Condition</strong></p>
<p>On the Condition tab, select Custom log search as the signal name and choose Aggregated logs as the query type.</p>
<p>Enter the following KQL query to identify VPN tunnel disconnection events during the last 10 minutes:</p>
<p>&nbsp;</p>
<img />
<p>&nbsp;</p>
<p>&nbsp;</p>
<p>AzureDiagnostics</p>
<p>| where TimeGenerated &gt; ago(10m)</p>
<p>| where Category == "TunnelDiagnosticLog"</p>
<p>| where status_s == "Disconnected"</p>
<p>| project TimeGenerated, Resource, status_s<br /><br /></p>
<p>Configure the measurement settings as follows:</p>
<ul>
<li>Measure: Table rows</li>
<li>Aggregation type: Count</li>
<li>Aggregation granularity: 5 minutes</li>
<li>Threshold type: Static</li>
<li>Operator: Greater than</li>
<li>Threshold value: 0</li>
</ul>
<p>This configuration triggers an alert whenever one or more tunnel disconnection events are detected.</p>
<p><strong>Actions</strong></p>
<p>On the Actions tab, select Use action groups and either choose an existing action group or create a new one. Configure the action group to send notifications through email, SMS, webhook, or other supported notification channels when a VPN tunnel disconnection event is detected. You can also customize the email subject to make alert notifications easier to identify and manage.<br />&nbsp;</p>
<p>&nbsp;</p>
<img />
<p>&nbsp;</p>
<p><strong>Details</strong></p>
<p>On the Details tab, provide a meaningful Alert Rule Name, select the appropriate Severity, and add a brief description of the alert. This information will help operations teams quickly understand the purpose and importance of the alert when it is triggered.</p>
<p><strong>Review + create</strong></p>
<p>Review all configuration settings to ensure they are correct, then select Create to deploy the alert rule. Azure Monitor will begin evaluating the configured query and automatically notify the specified recipients whenever a VPN tunnel enters a disconnected state.</p>
<p>&nbsp;</p>
<p><strong>Summary</strong></p>
<p>By combining Azure VPN Gateway diagnostic logs with Azure Monitor alert rules, organizations can proactively monitor VPN tunnel health and receive near real-time notifications when a tunnel disconnects. This approach improves operational visibility, reduces troubleshooting time, and helps maintain reliable hybrid connectivity between Azure and on-premises networks.</p>
</details>
