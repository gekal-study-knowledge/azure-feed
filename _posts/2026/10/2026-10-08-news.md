### Anyscale on Azure is now Generally Available

- **Link**: [https://techcommunity.microsoft.com/t5/apps-on-azure-blog/anyscale-on-azure-is-now-generally-available/ba-p/4562547](https://techcommunity.microsoft.com/t5/apps-on-azure-blog/anyscale-on-azure-is-now-generally-available/ba-p/4562547)
- **Published**: 2026-10-08 02:12:20
- **Fetched**: 2026-10-08 18:35:58

<details class="entry-summary">
<summary>詳細を表示</summary>
<p><a href="https://learn.microsoft.com/en-us/azure/anyscale-on-azure/overview" rel="noopener" target="_blank"><span><span>Anyscale</span><span> on Azure</span></span></a><span> is now Generally Available. Enterprises can run the Ray distributed runtime as a managed service on Azure Kubernetes Service (AKS),</span><span> with workloads running in the customer’s own Azure subscription, network, and identity boundary.&nbsp;</span><span>&nbsp;</span></p>
<p><span>With General Availability, Anyscale on Azure is ready for production workloads and comes with the commitments enterprises need. It is backed by a service level agreement and production support from both Microsoft and Anyscale. Customer workloads, datasets, and model artifacts run in their Azure subscription, while Anyscale operates the control plane in its own Azure tenant. Customers can use their Azure identity and governance controls for the resources in their subscription. </span><a href="https://www.youtube.com/watch?v=2v3vEPPkZTo" rel="noopener" target="_blank"><span><span>Xoople is already using </span><span>Anyscale on Azure</span></span></a><span> to turn planetary-scale satellite imagery into decision-ready intelligence.</span></p>
<p>&nbsp;</p>
<p><strong><span><span>AI systems need more than a good model</span></span><span>&nbsp;</span></strong></p>
<p><span>Model quality is only part of the challenge. Enterprises must also connect, secure, and operate the stages around the model.</span> <span>A typical stack assembles one tool for data preparation, another for distributed training, a third for evaluation, and a fourth for serving. Each tool solves part of the problem. Connecting them can require custom integration code, separately provisioned compute, and security controls that teams must maintain across systems.</span><span>&nbsp;</span></p>
<p><span>The resulting challenges fall into four areas:</span><span>&nbsp;</span></p>
<ul>
<li><strong><span>Utilization</span></strong><span>: GPUs provisioned per stage can sit idle while another stage waits for capacity. Reserved capacity that is idle is still billed.</span><span>&nbsp;</span></li>
</ul>
<ul>
<li><strong><span>Security and governance</span></strong><span>: Teams must manage who can access data and models, where they are processed, and how security controls are configured across each system and handoff.</span><span>&nbsp;</span></li>
</ul>
<ul>
<li><strong><span>Engineering time</span></strong><span>: Integration code requires ongoing maintenance, monitoring, and troubleshooting alongside the tools themselves.</span><span>&nbsp;</span></li>
</ul>
<ul>
<li><span><strong>Development cycle time</strong></span><span>: </span><span>Handoffs between stages can slow the path from experimentation to production.</span><span>&nbsp;</span></li>
</ul>
<p><span>Anyscale on Azure addresses this fragmentation by bringing data preparation, training, evaluation, and inference into a common runtime and operational model. Shared infrastructure can reduce idle compute capacity, while managed Ray cluster lifecycles reduce the infrastructure work teams perform themselves. Workloads, datasets, and model artifacts remain in the customer’s Azure subscription, where teams configure access and networking controls. Using a common runtime across stages can also reduce the need to maintain separate compute stacks.&nbsp;</span><span>&nbsp;</span></p>
<p><span>The goal is to support an AI learning loop, not just inference: production feedback informs data curation, training or post-training, and evaluation before updated models return to serving. Anyscale provides the common compute platform; teams remain responsible for their models, evaluation criteria, application workflows, and security configuration</span><span>.</span></p>
<p>&nbsp;</p>
<p><strong><span><span>How </span><span>Anyscale</span><span> on Azure </span><span>w</span><span>orks</span></span><span>&nbsp;</span></strong></p>
<p><a href="https://learn.microsoft.com/en-us/azure/anyscale-on-azure/overview" rel="noopener" target="_blank"><span><span>Anyscale on Azure</span></span></a><span> is an Azure Native Integration with an Anyscale-operated control plane and a customer data plane that keeps core resources in the customer’s Azure tenant, helping teams maintain their security and data-residency requirements.</span><span>&nbsp;</span></p>
<p>&nbsp;</p>
<img />
<p><span>Anyscale hosts and operates the control plane in Azure. You reach it from the Azure Portal, the Anyscale console, or the Anyscale CLI and SDK. The data plane runs entirely inside your own Azure subscription: Anyscale deploys an operator into your AKS cluster, which manages Ray cluster lifecycles on your behalf. This keeps Ray workloads, datasets, and model artifacts in your Azure subscription, while the Anyscale-hosted control plane processes operational metadata. Workloads run on AKS within your virtual network and use your existing Microsoft Entra ID, Azure RBAC, and private networking controls.</span><span>&nbsp;</span></p>
<p><span>The Anyscale operator and Ray clusters initiate outbound connections to the Anyscale control plane, so Anyscale does not require inbound firewall access to AKS nodes for those connections.&nbsp;</span><span>Anyscale on Azure integrates with Azure Managed Identities for authentication, Azure Blob Storage and ADLS for data, Azure Key Vault for secrets, and Azure Container Registry for images.</span><span>&nbsp;</span></p>
<p>&nbsp;</p>
<p><strong><span><span>Use familiar Azure identity and resource controls</span></span><span>&nbsp;</span></strong></p>
<p><span>Anyscale on Azure is backed by Azure Resource Manager, allowing platform teams to apply Azure Policy and discover Anyscale resources through Azure Resource Graph, just as they do with other Azure resources.</span><span>&nbsp;</span></p>

<p><strong><span><span>One runtime&nbsp;</span><span>for </span><span>the </span><span>entire </span><span>AI lifecycle</span></span><span>&nbsp;</span></strong></p>
<p>One Ray runtime supports data preparation, training and fine-tuning, batch and online inference, and long-running agentic workloads. When each stage has its own compute, capacity reserved for one can sit idle while another waits. A shared scheduler reallocates compute as demand shifts, which can reduce idle capacity and lower infrastructure costs.</p>
<img />
<p>Model choice also matters. Fine-tuned, task-specific models can cut serving costs when they meet quality requirements, so weigh total cost, not inference alone. The Anyscale Runtime supports Ray APIs, so existing Ray code needs fewer changes to move over. Customers should validate dependencies, data access, networking, and deployment configuration.</p>
