<h4><strong>What is HyperVelocity Engineering?</strong></h4>
<p>Hypervelocity Engineering (HVE) is Microsoft's engineering operating model designed to accelerate software and platform delivery through automation, reusable engineering patterns, platform engineering, AI-assisted development, and continuous feedback.</p>
<p>Unlike traditional methodologies, <strong>HVE is not another architecture framework or software product</strong>. Instead, it defines <strong>how engineering organizations operate</strong> to deliver secure, governed, and continuously improving solutions.</p>
<p>Its core philosophy is straightforward:</p>
<p><strong>Engineer platforms, automate everything practical, measure continuously, and improve through rapid feedback while keeping humans accountable for critical decisions.</strong></p>
<p>HVE combines several modern engineering disciplines into a unified operating model:</p>
<ul>
<li>Platform Engineering</li>
<li>Infrastructure as Code (IaC)</li>
<li>Policy as Code</li>
<li>Security by Design</li>
<li>AI-assisted engineering</li>
<li>Continuous observability</li>
<li>DevSecOps</li>
<li>Human-in-the-loop governance</li>
</ul>
<p>Together, these capabilities enable organizations to innovate faster without compromising security or compliance.</p>

<h4>The Core Principles of Hypervelocity Engineering</h4>
<p>Hypervelocity Engineering is built around six complementary principles.</p>
<p><strong>Outcome-Driven Engineering</strong></p>
<p>Every engineering decision should align with measurable business outcomes rather than technology adoption alone. Success is measured by customer value, not infrastructure deployment.</p>
<p><strong>Platform Engineering</strong></p>
<p>Rather than building infrastructure repeatedly for every project, organizations create reusable, self-service platforms that accelerate application delivery while maintaining consistency.</p>
<p><strong>Automation Everywhere</strong></p>
<p>Automation extends beyond deployments. Infrastructure provisioning, governance, security validation, policy enforcement, testing, and operations should all be automated wherever possible.</p>
<p><strong>Security by Design</strong></p>
<p>Security is integrated into every engineering stage—from identity and networking to deployment pipelines and operational monitoring—reducing risk while improving delivery speed.</p>
<p><strong>AI-Assisted Engineering</strong></p>
<p>AI enhances developer productivity by generating code, documentation, infrastructure templates, architecture recommendations, and testing artifacts. Humans remain responsible for validation and governance.</p>
<p>&nbsp;</p>
<p><strong>Continuous Observability and Feedback</strong></p>
<p>Operational insights, telemetry, cost analysis, and user feedback continuously improve future engineering decisions.</p>

### Azure Cobalt: Workload-Aware Power Management for More Efficient Datacenters

- **Link**: [https://techcommunity.microsoft.com/t5/azure-infrastructure-blog/azure-cobalt-workload-aware-power-management-for-more-efficient/ba-p/4537049](https://techcommunity.microsoft.com/t5/azure-infrastructure-blog/azure-cobalt-workload-aware-power-management-for-more-efficient/ba-p/4537049)
- **Published**: 2026-07-17 06:16:29
- **Fetched**: 2026-08-27 21:13:49

<p class="lia-align-justify"><span>As cloud services and AI workloads continue to grow, power has become a key constraint in expanding compute capacity. Using available power more efficiently enables Azure to deploy more servers in each datacenter, helping meet growing customer demand while improving sustainability. To address this challenge, Microsoft has taken a vertically integrated approach to infrastructure, co-designing hardware and software to optimize performance and efficiency across the stack. </span><span>&nbsp;</span></p>
<p class="lia-align-justify"><span>With Azure Cobalt CPUs, Microsoft introduced an industry-first per-virtual machine (VM) power monitoring and capping capability, developed from the ground up and deployed in Azure. Bringing this capability into production required hardware/software co-design across the Azure stack, spanning silicon and firmware, virtualization, server agents, VM placement systems, and datacenter power management infrastructure. By managing power at the granularity of individual VMs, Azure can preserve performance for critical workloads while improving overall infrastructure efficiency.</span><span>&nbsp;</span></p>
<h3><span class="lia-text-color-15"><strong>The Need for Fine-Grained Power Management to Enhance Efficiency</strong>&nbsp;</span></h3>
<p class="lia-align-justify"><span>A widely adopted strategy for improving datacenter power efficiency is </span><a href="https://www.microsoft.com/en-us/research/wp-content/uploads/2020/10/Per-VM-Capping-ATC21.pdf" rel="noopener" target="_blank"><span><span>o</span><span>versubscription</span></span></a> <span>— adding more servers within the same power budget to harvest the unutilized power and relying on power capping when power draw exceeds the limit. However, conventional hardware-based capping applies uniform CPU throttling across all cores. While this ensures power safety, it degrades performance for all VMs, including critical customer-facing workloads. This limitation restricts how aggressively Azure can oversubscribe power, since higher oversubscription levels cause more frequent and severe throttling, thereby degrading customer workload performance.</span><span>&nbsp;</span></p>
<p class="lia-align-justify"><span>To address these limitations, Azure initially introduced </span><a href="https://www.microsoft.com/en-us/research/wp-content/uploads/2020/10/Per-VM-Capping-ATC21.pdf" rel="noopener" target="_blank"><span><span>software-</span><span>only</span><span> per-VM power capping</span></span></a><span>. This system uses VM metadata and workload predictions to selectively throttle non-critical VMs (e.g., non-production workloads, batch jobs) through a userspace Azure agent, helping protect the performance of customer-facing production applications; the figure below shows the criteria used for determining each VM’s priority.&nbsp; However, software-based throttling is slow since it relies on fixed frequency change steps in a feedback loop that struggles to converge quickly.</span><span>&nbsp;</span></p>
<img />
<h3><span class="lia-text-color-15"><strong>Hardware/Software Co-design for Per-VM Power Management on Cobalt&nbsp;</strong></span></h3>
<p class="lia-align-justify">Building our own CPUs enabled Microsoft to extend software-only per-VM power capping into a more effective hardware/software co-design, with per-VM power monitoring and management built directly into Cobalt from the ground up. This industry-first capability, now deployed in Azure, preserves performance for critical customer workloads while enabling up to 20% more power oversubscription on Cobalt 200.</p>
<p class="lia-align-justify">In our implementation, the software provides VM identifiers (IDs) and each VM’s priority to the hardware. The hypervisor communicates a VM’s ID and priority to the hardware on VM core scheduling. CPU firmware uses VM priorities to maximize performance within a power budget. When power consumption exceeds the limit, it reduces power draw in priority order by lowering the voltage and frequency (<a href="https://en.wikipedia.org/wiki/Dynamic_frequency_scaling" rel="noopener" target="_blank">DVFS</a>) of each VM's cores. Since VM to core assignments can change due to context switches (at milliseconds scale), the firmware samples VM priorities of cores and re-evaluates power and core frequency every millisecond. The below figure illustrates the evolution of Azure's power management approach, from conventional hardware capping to per-VM (workload-aware) power management on Cobalt.</p>
<p class="lia-align-justify">&nbsp;</p>
<img />
<p class="lia-align-justify">&nbsp;</p>
<p class="lia-align-justify"><span>Furthermore, the firmware uses the programmed IDs to monitor per-VM power and frequency. This telemetry is used to understand the throttling experienced by VMs, build VM power models, and support energy/carbon reporting.</span><span>&nbsp;</span></p>
<h3><span class="lia-text-color-15"><strong>Real-World Impact&nbsp;&nbsp;</strong></span></h3>
<ul>
<li><strong>Co-designed per-VM power capping on Cobalt provides up to 24% higher performance</strong> than software-only capping under the same power budget, based on SPEC CPU Integer benchmarks. Cobalt provides the best (100%) performance for the top 5 priorities while the software-based approach can only do so for the top priority. Overall, Cobalt provides 2 – 24% higher performance.</li>
</ul>
<img />
<ul>
<li><strong>Prioritized capping on Cobalt 200 provides up to 20% more power oversubscription&nbsp;</strong>for the evaluated scenarios while preserving performance of critical VMs. It allows a 35% reduction in power with no performance impact to the critical VMs whereas no prioritization only allows a reduction of 15%. Azure can choose power savings between 15 to 35% based on tolerable performance impact to the non-critical VMs.</li>
</ul>
<img />
<p class="lia-align-justify">These results demonstrate that per-VM power management on Cobalt 200 helps preserve performance for critical workloads while improving efficiency. By applying power limits more selectively, Azure can use power more effectively <span>—</span> deploying more servers within its existing datacenter footprint to meet growing customer compute demand and improve sustainability.</p>
<h3><span class="lia-text-color-15"><strong>End-to-End Integration across the Azure Stack&nbsp;</strong></span></h3>
<p class="lia-align-justify">The figure below shows the end-to-end architecture for per-VM power management on Cobalt and highlights the hardware and software enhancements across the Azure stack. The VM scheduler places VMs in racks with available power and live migrates VMs from constrained racks using workload criticality and measured VM power. The node agent provides each VM’s ID and priority to the hypervisor, which tags the VM’s cores during scheduling. Each VM's ID enables per-VM telemetry, while its priority guides power management decisions. The per-VM telemetry is sent to Resource Central for building and refining prediction models. Finally, the power manager monitors power consumption across server groups, such as racks and rows. When a power limit is reached, it signals servers to reduce usage. The Cobalt CPU on each server then uses VM priorities to selectively throttle lower-priority workloads, preserving performance for critical applications while maintaining power safety.</p>
<img />
<h3><span class="lia-text-color-15"><strong>Looking Ahead&nbsp;</strong></span></h3>
<p class="lia-align-justify">This work exemplifies the power of hardware/software co-design in cloud infrastructure and is a consequence of deep collaboration across many hardware and software teams within Microsoft. As cloud workloads continue to evolve, innovations like co-designed per-VM power management will be essential to balance performance, efficiency, and sustainability.</p>
