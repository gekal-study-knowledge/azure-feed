### Introducing Azure Front Door edge actions - Bringing secure, programmable logic to the edge

- **Link**: [https://techcommunity.microsoft.com/t5/azure-networking-blog/introducing-azure-front-door-edge-actions-bringing-secure/ba-p/4531928](https://techcommunity.microsoft.com/t5/azure-networking-blog/introducing-azure-front-door-edge-actions-bringing-secure/ba-p/4531928)
- **Published**: 2026-07-21 00:32:26
- **Fetched**: 2026-08-27 21:13:49

<details class="entry-summary">
<summary>詳細を表示</summary>
<p><span>Modern web applications are expected to feel instant, secure, and personalized, no matter where users connect from or what device they use. Delivering that experience requires more than moving static content closer to users. It increasingly depends on making smart decisions at the edge, from validating requests and selecting the right origin to personalizing responses and stopping suspicious traffic before it reaches the backend.</span><span>&nbsp;</span></p>
<p><span>Because of this, over the last decade, compute resources for web applications have steadily moved closer to users. What began with content caching at the edge quickly evolved into dynamic routing, security enforcement, and intelligent application traffic management. Today, enterprises expect even more: programmable compute at the edge! Developers and platform teams want the flexibility to run lightweight logic at the edge without giving up the scale, security, and operational confidence they expect from Azure.</span><span>&nbsp;</span></p>
<p><a href="https://learn.microsoft.com/azure/frontdoor/front-door-overview" rel="noopener" target="_blank"><span><span>Azure Front Door</span></span></a><span> through its </span><a href="https://learn.microsoft.com/azure/frontdoor/front-door-rules-engine?pivots=front-door-standard-premium" rel="noopener" target="_blank"><span><span>rulesets</span></span></a><span> offers a robust, declarative framework for applying common traffic management and security policies, such as redirects, header manipulation, and conditional routing. They are optimized for scenarios where behavior can be defined statically and evaluated efficiently at scale.</span><span>&nbsp;</span></p>
<p><span>As customer workloads become more dynamic, and application logic increasingly moves closer to the user, additional capabilities are often required beyond declarative configuration.</span><span>&nbsp;</span></p>
<h1 id="mcetoc_1jsaf89fc_1"><span><span>Meet Azure Front Door edge actions, now in public preview</span></span></h1>
<p>&nbsp;</p>
<p><span>We are excited to announce </span><a href="https://learn.microsoft.com/azure/frontdoor/edge-actions" rel="noopener" target="_blank"><span><span>Azure Front Door edge actions</span></span></a><span> which represent Microsoft’s next step in this evolution. With edge actions, customers can execute custom logic directly at Microsoft’s global edge, enabling new classes of real-time personalization, security, and resiliency scenarios, without pushing complexity back to origins!</span><span>&nbsp;</span></p>
<p>&nbsp;</p>
<img />
<p><span>&nbsp;</span></p>
<p>&nbsp;</p>
<p><span>Edge actions allow customers to author </span><strong><span>lightweight JavaScript functions</span></strong><span> that execute as part of Azure Front Door request processing. In the current public preview, edge actions are invoked during the client request phase and are attached to Azure Front Door routes through </span><a href="https://learn.microsoft.com/en-us/azure/frontdoor/front-door-rules-engine?pivots=front-door-standard-premium" rel="noopener" target="_blank"><span><span>rulesets</span></span></a><span>.</span><span>&nbsp;</span></p>
<p><span>This tight integration means edge actions work seamlessly with existing Azure Front Door capabilities, including Web Application Firewall (WAF), caching, and routing - while extending them with programmable logic. Customers can incrementally adopt edge actions without re-architecting their applications or delivery pipelines.&nbsp;&nbsp;&nbsp;&nbsp;</span><span>&nbsp;</span></p>
<p><span>&nbsp;</span></p>
<h2 id="mcetoc_1jsaf89fd_2"><span><span>What can you build with edge actions today</span></span><span>&nbsp;</span></h2>
<p>&nbsp;</p>
<p><span>Edge actions in public preview are optimized for lightweight, latency-sensitive scenarios that benefit from immediate decision-making. Common use cases include:&nbsp;</span><span>&nbsp;</span></p>
<ul>
<li><span><strong>A/B experimentation and canary rollouts:</strong> </span><span>Evaluate request context at the edge and route users to different application experiences or releases without adding origin-side decision logic.</span><span>&nbsp;</span></li>
</ul>
<ul>
<li><span><strong>Request and response header manipulation:</strong> </span><span>Add, remove, or transform headers to support security controls, experimentation, routing, and application modernization patterns.</span><span>&nbsp;</span></li>
</ul>
<ul>
<li><strong><span>Request rejection:</span></strong><span> Stop unwanted, malformed, or unauthorized requests before they consume origin resources.</span><span>&nbsp;</span></li>
</ul>
<ul>
<li><span><strong>Dynamic origin selection:</strong> </span><span>Choose the best origin based on request attributes, health signals, geography, device type, or business logic.</span><span>&nbsp;</span></li>
</ul>
<ul>
<li><span><strong>URL rewrite and redirect:</strong> </span><span>Adapt paths or redirect users at the edge to simplify migrations, campaign launches, localization, and application routing.</span><span>&nbsp;</span></li>
</ul>
<ul>
<li><span><strong>Authentication and authorization scenarios:</strong> </span><span>Validate tokens or request attributes close to the user, helping protect applications before traffic reaches backend services.</span><span>&nbsp;</span></li>
</ul>
<p><span>Please refer to&nbsp;<span><span><a class="lia-external-url" href="https://github.com/Azure/EdgeActionsSamples" rel="noopener" target="_blank">Azure/EdgeActionsSamples</a></span></span></span><span> to start building edge actions today.</span></p>
<p>&nbsp;</p>
<h1 id="mcetoc_1jsaf89fd_3"><span><span>Designed for</span><span> industry leading</span><span> security-first edge compute&nbsp;&nbsp;</span></span><span>&nbsp;</span></h1>
<p>&nbsp;</p>
<p><span>Running customer-defined code at the edge introduces unique security challenges. Edge environments now process untrusted user code at massive scales, making strong isolation non-negotiable for Azure.&nbsp;</span><span>&nbsp;</span></p>
<p><span>Enter </span><a href="https://aka.ms/hyperlight-announcement" rel="noopener" target="_blank"><span><span>Hyperlight</span></span></a><span>: Microsoft’s foundation for secure execution. With Hyperlight, each edge action code runs in its own lightweight, hardware-backed micro-VM - like a secure apartment, isolated from neighbors. Unlike traditional virtual machines, Hyperlight micro</span>‑<span>VMs are extremely lightweight and do not have a general-purpose guest operating system. Because of their small footprint, they provide a much more reduced attack surface with a hardware-backed isolation boundary between every instance of customer code, the host infrastructure, and other tenants.</span><span>&nbsp;</span></p>
<p><span>This model allows Azure Front Door to combine the safety properties of hardware virtualization with the performance characteristics required for edge compute. Customer code is isolated by design to reduce blast radius to a single instance, helping protect both the platform and neighboring workloads.</span><span>&nbsp;</span></p>
<h1 id="mcetoc_1jsaf89fd_4"><span><span>How edge actions fit into the request path </span></span><span>&nbsp;</span></h1>
<p>&nbsp;</p>
<p><span>When a client request reaches Azure Front Door, it follows Azure Front Door’s standard routing pipeline. The request is first evaluated against any configured WAF policies and routing rules. If a rule is configured to invoke an edge action, execution is handed off to the edge actions runtime (Hyperlight) at the edge POP.&nbsp;</span><span>&nbsp;</span></p>
<p><span>At execution time, Azure Front Door provides the edge action with a constrained, immutable context that includes request metadata, server variables, origin health information, and geo or device signals. The edge action can then modify the request, generate a response, or influence routing decisions, all within strict execution and resource limits designed to preserve platform stability.</span><span>&nbsp;</span></p>

<h1 id="mcetoc_1jsaf89fd_5"><span><span>Ship safely with versions and execution filters</span></span><span>&nbsp;</span></h1>
<p>&nbsp;</p>
<p><span>Edge actions are built for operational confidence. Each edge action supports multiple versions of code, and customers can control which version executes using&nbsp;</span><a href="https://learn.microsoft.com/azure/frontdoor/edge-actions#execution-filters" rel="noopener" target="_blank"><span><span>execution filters</span></span></a><span>. This enables header-based routing, canary deployments, and A/B testing scenarios without downtime.&nbsp;</span><span>&nbsp;</span></p>
<p><span>Teams can gradually introduce new logic, validate behavior with real traffic, and roll back instantly if needed, bringing modern DevOps practices directly to the edge.</span><span>&nbsp;</span></p>
<p><span>&nbsp;</span></p>
<h1 id="mcetoc_1jsaf89fd_6"><span><span>Observe and </span><span>operate</span><span> with confidence</span></span><span>&nbsp;</span></h1>
<p>&nbsp;</p>
<p><span>Edge actions integrate with Azure’s existing </span><a class="lia-external-url" href="https://learn.microsoft.com/azure/frontdoor/edge-actions#edge-action-logs" rel="noopener" target="_blank">observability stack</a><span>. Customers can emit logs from their edge action code and correlate execution results with Azure Front Door access and routing logs. This unified view simplifies troubleshooting and provides visibility into edge execution behavior in production environments.</span><span>&nbsp;</span></p>
