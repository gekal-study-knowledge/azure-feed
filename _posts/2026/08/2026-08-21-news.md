## Apps on Azure Blog

### Announcing Azure Web PubSub chat in public preview

- **Link**: [https://techcommunity.microsoft.com/t5/apps-on-azure-blog/announcing-azure-web-pubsub-chat-in-public-preview/ba-p/4548907](https://techcommunity.microsoft.com/t5/apps-on-azure-blog/announcing-azure-web-pubsub-chat-in-public-preview/ba-p/4548907)
- **Published**: 2026-08-21 18:31:22
- **Fetched**: 2026-08-27 21:13:50

<p>Chat is becoming a standard interaction model across customer support, collaboration, gaming, marketplaces, healthcare, financial services, and AI-powered applications. But building a production-ready chat system involves much more than opening a WebSocket connection. Teams also need to manage rooms and membership, deliver and order messages, retain conversation history, recover from connection interruptions, and enforce permissions.</p>
<p>Today, we are excited to announce that <strong>Azure Web PubSub chat is available in public preview</strong>. Azure Web PubSub chat is a managed capability built on Azure Web PubSub. It provides chat-focused client and server APIs so developers can work directly with familiar concepts such as&nbsp;<strong>rooms, messages, members, users, and roles</strong>, while Azure manages the underlying real-time messaging infrastructure.</p>
<h2>Focus on the chat experience, not the messaging plumbing</h2>
<p>Azure Web PubSub already helps developers build large-scale, real-time applications. The new chat capability adds a higher-level abstraction for applications whose primary interaction model is conversation. Instead of defining custom events, message schemas, membership logic, persistence workflows, and reconnect behavior, developers can use built-in chat operations to:</p>
<ul>
<li>Create one-to-one or group rooms.</li>
<li>Add and remove room members.</li>
<li>Send ordered messages in real time.</li>
<li>Retrieve persistent room message history.</li>
<li>Apply built-in or custom roles and permissions.</li>
<li>Reconnect clients and recover messages after temporary connection loss.</li>
</ul>
<p>These capabilities run on Azure Web PubSub infrastructure and inherit its automatic scaling, geo-replication, security, and compliance foundations.</p>
<h2>Chat-native APIs for clients and servers</h2>
<p>Azure Web PubSub chat provides two complementary ways to build.</p>
<p>The <strong>JavaScript client SDK</strong>, available through the `@azure/web-pubsub-chat-client` npm package, connects applications to a chat hub. Clients can create rooms, exchange messages, load history, manage members, and subscribe to chat events.</p>
<p>The <strong>Chat REST API</strong> supports trusted server-side and administrative workflows, including managing rooms, users, members, messages, roles, and permissions. This separation lets client applications deliver responsive real-time experiences while backend services retain control over identity, moderation, governance, and business rules.</p>
<p>For example, after connecting a `ChatClient`, creating a room and sending a message takes only a few calls:</p>
const room = await client.createRoom("Project Falcon", ["bob", "carol"]);
client.on("message", ({ message }) =&gt; {
     console.log(`${message.createdBy}: ${message.content.text}`);
});
await client.sendToRoom(room.roomId, "Welcome to the project room!");
<p>Applications can also read message history through an asynchronous iterator, making it straightforward to implement initial conversation loading or incremental history as a user scrolls.</p>
<h2>Keep chat data in your Azure Storage account</h2>
<p>Persistent chat data remains in an Azure Storage account selected by the application owner. Azure Web PubSub chat uses the Web PubSub resource's managed identity to access that storage, avoiding storage connection strings or keys in the chat configuration.</p>
<p>The stored data includes:</p>
<ul>
<li>Messages and conversation history</li>
<li>Rooms and room membership</li>
<li>Users</li>
<li>Roles and permissions</li>
</ul>
<p>Your data stays in your storage account, and the service keeps no separate copy. This model gives organizations direct ownership of their persisted chat data while the managed service handles real-time delivery and chat operations.</p>
<h2>Built-in access control with room-level flexibility</h2>
<p>Chat applications often need different privileges for participants, moderators, room owners, support agents, or automated services. Azure Web PubSub chat includes a role and permission model for these scenarios.</p>
<p>Built-in room roles distinguish between <strong>members</strong> and <strong>operators</strong>. Both can send messages, read history, and invite members by default, while operators can also remove users. Developers can define custom user or room roles when an application needs a different permission set. Role administration is performed through the Chat REST API, keeping permission management in trusted server-side code.</p>
<h2>Reliable conversations across connections and devices</h2>
<p>Users expect chat to continue working when a laptop changes networks, a mobile connection briefly drops, or the same account is open in multiple browser tabs or devices. Azure Web PubSub chat runs on Azure Web PubSub's reliable WebSocket connection. The client reconnects and recovers automatically after an interruption, while the service fans messages out to a user's active connections. Persistent history also allows users to load earlier messages after reconnecting or joining a room later.</p>
<h2>Choose the right Web PubSub capability</h2>
<p>The new chat capability complements the existing standard Web PubSub hub. Use a&nbsp;<strong>chat hub</strong> when the application is centered on conversations and benefits from built-in rooms, membership, history, roles, and chat-focused APIs. Use a&nbsp;<strong>standard hub</strong> when the application needs full control over its protocol or supports a different real-time workload, such as telemetry, device signaling, multiplayer state, notifications, or live dashboards. Both options use Azure Web PubSub, allowing teams to select the abstraction that best fits each real-time scenario.</p>
<h2>Get started</h2>
<p>To try Azure Web PubSub chat:</p>
<ol>
<li>Create or open an Azure Web PubSub resource.</li>
<li>Link an Azure Storage account under <strong>Persistent Storages</strong>.</li>
<li>Add a <strong>Chat Hub</strong>&nbsp;and associate it with that storage.</li>
<li>Generate a client access URL for testing.</li>
<li>Install the JavaScript client SDK:</li>
</ol>
npm install azure/web-pubsub-chat-client
<ol start="6">
<li>Connect a client, create a room, and send your first message.</li>
</ol>
<p>The portal-generated client URL is intended for experimentation. In production, issue client access URLs from an authenticated backend and derive the chat user ID from the signed-in application identity. Managed identity and Microsoft Entra ID can be used for keyless server authentication.&nbsp;</p>
<p>Azure Web PubSub chat is available now in public preview. Start with the&nbsp;<a href="https://learn.microsoft.com/azure/azure-web-pubsub/chat-overview" rel="noopener" target="_blank">Azure Web PubSub chat overview</a>, follow the <a href="https://learn.microsoft.com/azure/azure-web-pubsub/chat-quickstart" rel="noopener" target="_blank">quickstart</a>, or explore the <a href="https://learn.microsoft.com/azure/azure-web-pubsub/chat-reference-sdk-and-rest" rel="noopener" target="_blank">client SDK and REST API</a>. We look forward to seeing the customer conversations, collaboration experiences, and AI-powered applications you build with it.</p>
