## Azure Networking Blog

### Scale limits in network security perimeter

- **Link**: [https://techcommunity.microsoft.com/t5/azure-networking-blog/scale-limits-in-network-security-perimeter/ba-p/4542911](https://techcommunity.microsoft.com/t5/azure-networking-blog/scale-limits-in-network-security-perimeter/ba-p/4542911)
- **Published**: 2026-08-01 02:24:48
- **Fetched**: 2026-08-27 21:13:49

<p>Presently, network security perimeter functionality can be used to support deployments of PaaS resources with common public network controls with following scale limitations:</p>
<div class="styles_lia-table-wrapper__h6Xo9 styles_table-responsive__MW0lN"><table><thead><tr><th><strong>Limitation</strong></th><th><strong>Description</strong></th></tr></thead><tbody><tr><td><strong>Number of network security perimeters</strong></td><td>Supported up to 100 as recommended limit per subscription.</td></tr><tr><td><strong>Profiles per network security perimeters</strong></td><td>Supported up to 200 as recommended limit.</td></tr><tr><td><strong>Number of rule elements per profile</strong></td><td>Supported up to 200 for inbound and outbound each as hard limit.</td></tr><tr><td><strong>Number of PaaS resources across subscriptions associated with the same network security perimeter</strong></td><td>Supported up to 1000 as recommended limit.</td></tr></tbody></table></div>
<p>These limits were deployed as soft limits. The updated limits will be as given in the table below and will now be implemented as hard limits</p>
<div class="styles_lia-table-wrapper__h6Xo9 styles_table-responsive__MW0lN"><table style="width: 100%; height: 221.333px;"><thead><tr style="height: 34.6667px;"><th style="height: 34.6667px;"><strong>Limitation</strong></th><th style="height: 34.6667px;"><strong>Description</strong></th></tr></thead><tbody><tr style="height: 34.6667px;"><td style="height: 34.6667px;"><strong>Number of network security perimeters</strong></td><td style="height: 34.6667px;">Supported up to <strong>1000</strong> as <strong>hard limit</strong> per subscription.</td></tr><tr style="height: 34.6667px;"><td style="height: 34.6667px;"><strong>Profiles per network security perimeters</strong></td><td style="height: 34.6667px;">Supported up to 200 as <strong>hard limit</strong>.</td></tr><tr style="height: 58.6667px;"><td style="height: 58.6667px;"><strong>Number of rule elements per profile</strong></td><td style="height: 58.6667px;">Supported up to 200 for inbound and outbound each as <strong>hard limit</strong>.</td></tr><tr style="height: 58.6667px;"><td style="height: 58.6667px;"><strong>Number of PaaS resources across subscriptions associated with the same network security perimeter</strong></td><td style="height: 58.6667px;">Supported up to 2500 as <strong>hard limit</strong>.</td></tr></tbody></table></div>
<p><u><strong>What do the changes mean to users?</strong></u></p>
<ol>
<li>Rule elements' creation limit will be capped at 200 for new customers. (presently at 500)</li>
<li>Existing customers who have <strong>rule elements &gt;200 per profile</strong>, will be allowed to continue above 200 with an option to&nbsp;<em><strong>replace/edit, decrease/reduce but not increase/add</strong></em> the current rule elements without any service interruption <strong>till 10/31/26</strong>.
<ol>
<li>For example, scenario(s): A user has a profile with rule elements = 400&nbsp;
<ol>
<li>They cannot increase/add new rule elements and try to go above 400.</li>
<li>They can replace/edit existing rule elements and continue at 400.</li>
<li>They can decrease/reduce rule elements to anything till 200 and that will be their upper ceiling i.e. if they reduce to 250, that will be their new upper ceiling.</li>
<li>If they decrease/reduce to &lt;200, say 150, they can go till 200 but not back to the 400.</li>
</ol>
</li>
</ol>
</li>
<li><strong>After 10/31/26</strong>, profiles with rule elements above 200 will be allowed to continue above 200 but <em><strong>only with an option to reduce</strong></em>. There will be <em><strong>no replace/edit and increase</strong></em> options.
<ol>
<li>For example, scenario(s): A user has a profile with rule elements = 400
<ol>
<li>They cannot increase/add new rule elements and try to go above 400.</li>
<li>They cannot replace/edit existing rule elements but can continue at 400 without touch the rule-elements.</li>
<li>They can decrease/reduce rule elements to anything till 200 but cannot stop above 200 or maintain above 200.</li>
<li>If they decrease/reduce to &lt;200, say 150, they can go till 200 but not back to the 400.</li>
</ol>
</li>
</ol>
</li>
</ol>
