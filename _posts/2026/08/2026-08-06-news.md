## Azure Networking Blog

### Announcing Public Preview - Azure Private Link over IPv6

- **Link**: [https://techcommunity.microsoft.com/t5/azure-networking-blog/announcing-public-preview-azure-private-link-over-ipv6/ba-p/4543978](https://techcommunity.microsoft.com/t5/azure-networking-blog/announcing-public-preview-azure-private-link-over-ipv6/ba-p/4543978)
- **Published**: 2026-08-06 02:06:27
- **Fetched**: 2026-08-27 21:13:49

<h2>1. Overview</h2>
<p>Private Link over IPv6 (PL IPv6) enables customers to securely access Azure PaaS services over&nbsp;<strong>IPv6-based connectivity.</strong></p>
<p>This capability is critical for:</p>
<ul>
<li>IPv6 based PE connectivity to PaaS resources</li>
<li>Enabling IPv6 in On-prem environments</li>
</ul>
<img />
<p><em>This document is intended to serve as guide to setup and test the On-prem connectivity from&nbsp;<strong>IPv6 customer address</strong> to Azure PaaS resources over Express Route via Private link. (IPv6 PE connectivity)</em></p>
<p><em>Note: This feature is currently in public preview and is not recommended for production workloads.&nbsp;</em></p>
<h2>2. Supported Scenarios</h2>
<p><strong>Scenario A: Native Azure (Azure VM → PaaS via IPv6 Private Endpoint)</strong></p>
<ul>
<li>IPv6 client VM in VNet → IPv6 Private Endpoint → Azure PaaS</li>
</ul>
<p><strong>Scenario B: OnPrem Access via ExpressRoute</strong></p>
<ul>
<li>On-prem IPv6 client → ExpressRoute → VNet Routing Appliance (VNRA) à IPv6 Private Endpoint → PaaS</li>
<li>Supported via <strong>ER Circuits</strong></li>
</ul>
<h2>3. Prerequisites</h2>
<h3>3.1 Supported Regions (Preview Scope)</h3>
<ul>
<li>Limited&nbsp;<strong>preview regions</strong></li>
<ul>
<li>West Central US</li>
<li>East Asia</li>
<li>UK South</li>
<li>US Central</li>
<li>North Europe</li>
</ul>
</ul>
<h3>3.2 Supported Services (Preview)</h3>
<ul>
<li>Azure Storage</li>
<li>Azure SQL</li>
<li>Azure Key Vault</li>
<li>Azure Data Explorer</li>
</ul>
<h3>3.3. Subscription registration</h3>
<p>An Azure account with an active subscription.&nbsp;<a href="https://azure.microsoft.com/free/?WT.mc_id=A261C142F&amp;cid=msft_learn_dab3b5ab-1c3f-1f6f-0dbc-2a913538e6f9" rel="noopener" target="_blank">Create an account for free</a>.</p>
<ul>
<li>Your subscription must be registered for the Private Link over IPv6 preview. Registration is mandatory before you configure any resources. You can self-register the subscription by running the following commands:<br /><em>az feature register --namespace Microsoft.Network --name SupportIPv6PrivateEndpoint --subscription &lt;subscription-id&gt; </em><br /><em>az provider register --namespace Microsoft.Network</em></li>
</ul>
<h2>4. Configurations</h2>
<h3>4.1 Azure VNET level configurations</h3>
<p>Please note that you will need to create:</p>
<ul>
<li>Dual-stack IPv6-enabled Vnet with a VM that is assigned both IPv4 and IPv6 address. For on-prem connectivity, this is the same Vnet where ER Gateway is created.<br />Refer: <a href="https://learn.microsoft.com/en-us/azure/virtual-network/ip-services/create-vm-dual-stack-ipv6-portal?tabs=azureportal" rel="noopener" target="_blank">Create an Azure virtual machine with a dual-stack network - Azure Virtual Network | Microsoft Learn</a></li>
<li>PL scale enabled on VNET via configuration flags (refer config flags mentioned further in this section and bolded flags in the code snippet)</li>
<li>Dual Stack (IPv4+ IPv6) Subnet</li>
<li>Private Endpoints with IPv6</li>
</ul>
<p>Refer these flags for enabling VNET with PL scale:</p>
<p>Vnet level : <br /><strong><em>"privateEndpointVNetPolicies": "Basic",</em></strong></p>
<p>Subnet level: <br /><strong><em>“privateEndpointNetworkPolicies": "RouteTableEnabled"<br /></em></strong></p>
<p>Refer Azure documentation for VNET creation: <a href="https://learn.microsoft.com/en-us/azure/virtual-network/quickstart-create-virtual-network?tabs=portal" rel="noopener" target="_blank">Quickstart: Create an Azure Virtual Network | Microsoft Learn</a></p>
<p>&nbsp;</p>
<h3>4.3 Private endpoint configuration:</h3>
<p>With the Private Link IPv6 support, we have introduced a new parameter in PE creation API/CLI, <strong>‘ip VersionType’.</strong> Please ensure that this is set to ‘IPv6’ for enabling PL IPv6 traffic.</p>
<p>Refer Azure documentation for PE creation: <a href="https://learn.microsoft.com/en-us/azure/private-link/create-private-endpoint-portal?tabs=dynamic-ip" rel="noopener" target="_blank">Quickstart: Create a private endpoint - Azure portal - Azure Private Link | Microsoft Learn</a></p>
<p><em>Reference CLI:</em></p>
<p><em>az network private-endpoint create \</em></p>
<p><em>&nbsp; --name &lt;private-endpoint-name&gt; \</em></p>
<p><em>&nbsp; --resource-group &lt;resource-group-name&gt; \</em></p>
<p><em>&nbsp; --vnet-name &lt;vnet-name&gt; \</em></p>
<p><em>&nbsp; --subnet &lt;subnet-name&gt; \</em></p>
<p><em>&nbsp; --private-connection-resource-id &lt;resource-id-of-target-service&gt; \</em></p>
<p><em>&nbsp; --group-id &lt;group-id&gt; \</em></p>
<p><em>&nbsp; --connection-name &lt;connection-name&gt; \</em></p>
<p><em>&nbsp; --location &lt;region&gt; \</em></p>
<p><em>&nbsp; --ip-version-type &lt;Ipv4|Ipv6 &gt;</em></p>
<p>&nbsp;</p>
<h3>4.4 DNS Configuration</h3>
<p>Ensure these points for DNS configurations:</p>
<ul>
<li>Create Private DNS Zone for each Service type</li>
<li>Attach the respective DNS zone to the Private Endpoints.</li>
<li>Ensure to check that after above steps completed PaaS FQDN resolves to PEIPv6 address.</li>
</ul>
<p>Refer Azure documentation for On-prem access via Private Link: <br /><a href="https://learn.microsoft.com/en-us/azure/private-link/private-endpoint-dns-integration#virtual-network-and-on-premises-workloads-using-a-dns-forwarder" rel="noopener" target="_blank">Azure Private Endpoint DNS Integration Scenarios | Microsoft Learn</a></p>
<h4>Native Azure Connectivity (Azure VM → PaaS via IPv6)</h4>
<p><strong>Validation:</strong></p>
<ul>
<li>Ensure the Storage Account FQDN resolves to the IPv6 Private Endpoint address.</li>
<li>Access the Storage Account using the standard service FQDN.</li>
</ul>
<p>&nbsp;</p>
<p>From the dual-stack VM:</p>
<p><em>nslookup &lt;storageaccount&gt;.blob.core.windows.net</em></p>
<p>Expected Result:</p>
<p><em>&lt;storageaccount&gt;.privatelink.blob.core.windows.net</em></p>
<p><em>AAAA: &lt;Private Endpoint IPv6 Address&gt;</em></p>
<p>&nbsp;</p>
<p><em><u>Connectivity validation:</u></em></p>
<p><em>curl https://&lt;storageaccount&gt;.blob.core.windows.net</em></p>
<p><em>Test-NetConnection &lt;storageaccount&gt;.blob.core.windows.net -Port 443</em></p>
<h4>Configurations specific to On-prem connectivity via ER circuit and Virtual Network Routing Appliance</h4>
<p>On-premises IPv6 clients access IPv6 private endpoints over ExpressRoute through a Virtual Network Routing Appliance (VNRA). ExpressRoute forwards traffic from on-premises IPv6 clients to the VNRA, which then routes the traffic to the target IPv6 private endpoint that's hosted by the Azure PaaS service.</p>
<p>This connectivity requires the following components:</p>
<ul>
<li>An ExpressRoute circuit with the appropriate gateway SKU for your connectivity type (FastPath or standard). For more information, see&nbsp;<a href="https://review.learn.microsoft.com/en-us/azure/expressroute/expressroute-howto-circuit-portal-resource-manager" rel="noopener" target="_blank">Create and modify an ExpressRoute circuit</a>.</li>
</ul>
<h3>4.5 Virtual Network Routing Appliance (VNRA) configurations</h3>
<p>To know more about VNRA, refer: <a href="https://learn.microsoft.com/en-us/azure/virtual-network/virtual-network-routing-appliance-overview" rel="noopener" target="_blank">Overview of Routing Appliances - Azure Virtual Network | Microsoft Learn</a></p>
<ul>
<li>We are leveraging VNRA to facilitate PL IPv6 ER traffic forwarding. User would be required to create a VNRA in the VNet.</li>
<li>To facilitate the forwarding of PL IPv6 traffic via VNRA, a UDR would be required to be added in the gateway subnet with next hop as VNRA IPv6 address. Below are the guided steps to achieve all of this.</li>
</ul>
<h5><em>Step 1: Create a VNRA in the VNet</em></h5>
<p>Create a VNRA in your resource group via Azure Preview portal.</p>
<ol>
<li>Search for Azure Virtual Network routing appliance on the Azure portal search</li>
</ol>
<p>&nbsp;</p>
<img />
<p>&nbsp;</p>
<p>&nbsp;</p>
<ol start="2">
<li>Click on create:<br /><img /></li>
<li>In the above creation page, choose your subscription and resource group, enter name, region, capacity (10-200 Gbps) &amp; the VNet.</li>
<li>Review and Create the VNRA.<br /><br /></li>
</ol>
<h5><em>Step 2: Create User Defined Route (UDR) to VNRA</em></h5>
<p>The UDR will ensure ER PLIPv6 traffic is forwarded to VNRA which will further process &amp; forward the traffic to the IPv6 Private Endpoint.</p>
<p>1.Create a new route table on Azure portal:</p>
<img />
<p>2. Choose the subscription, resource group and set ‘Gateway propagation’ as default (true)</p>
<p>3. Add a route in this route table to forward the on-prem PLIPv6 traffic to VNRA (for this please add route as shown in reference below) as per below details:</p>
<ul>
<li>Enter ‘Destination type’ as ‘IP Address’</li>
<li>Enter ‘Destination IP addresses/CIDR Ranges’ as Private Endpoint IPv6 subnet range - This is the subnet on which your Private Endpoint resides to which the traffic would be sent</li>
<li>Enter ‘Next hop’ as “Virtual Appliance”,</li>
<li>Give the ‘Next hop address’ as the IPv6 address of VNRA<br /><br /><img /></li>
</ul>
<p>4.Attach this route table to the Gateway subnet</p>
<p>&nbsp;</p>
<img />
<p>This completes the VNRA setup.</p>
<h2>5. Validate Connectivity</h2>
<p>After establishing configuration and deploying your setup, you can run following validations:</p>
<p>From OnPrem VM:</p>
<ul>
<li>Perform DNS lookup on PaaS FQDN → confirm IPv6 PE resolution</li>
<li>Connect using PaaS FQDN</li>
</ul>
<p><strong>Validation Checks</strong></p>
<ul>
<li>VM → PE connectivity over IPv6</li>
<li>Data plane traffic successful</li>
</ul>
<h2>6. Preview Considerations</h2>
<ul>
<li>Limited regional availability (Check preview regions above)</li>
<li>Destination PaaS resource must be in the same region as the Private Endppint. Cross region connectivity is not supported in this release.</li>
<li>Limited PaaS onboarding (Azure Storage, Azure SQL, Azure Key Vault, Azure Data Explorer)</li>
<li>Current on-premises connectivity support is limited to ExpressRoute-based scenarios and does not currently include VPN, Virtual WAN (vWAN), or Network Virtual Appliances (NVAs).</li>
<li>In Private Link IPv6 scenarios, the original client IPv6 address is not preserved in downstream service logs. Due to implicit NAT translation, logs will display the VNet-side translated source IP address instead.</li>
</ul>
