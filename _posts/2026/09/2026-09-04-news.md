### Building 3IQ Retail Assistant Demo – Part 3

- **Link**: [https://techcommunity.microsoft.com/t5/azure-architecture-blog/building-3iq-retail-assistant-demo-part-3/ba-p/4547233](https://techcommunity.microsoft.com/t5/azure-architecture-blog/building-3iq-retail-assistant-demo-part-3/ba-p/4547233)
- **Published**: 2026-09-04 02:23:13
- **Fetched**: 2026-09-04 10:36:48

<details class="entry-summary">
<summary>詳細を表示</summary>
<p>We are now at the last part of our demo. We will build a Copilot Agent to connect it to a SharePoint List holding data related to Support case raised by the customers. Then connect the other 2 agents (Fabric Data Agent and Foundry Prompt Agent) to it. But before doing it ensure Work IQ is activated with your Copilot, and you can build agents in Copilot Studio using Work IQ. Contact your Admin if it is not available. Also, Go ahead and rescale the Fabric Capacity to F64 and Resume it from the Azure Portal.</p>
<p><strong>Setting up SharePoint List &nbsp;</strong></p>
<p>Create a list in your M365 SharePoint site of choice and add the following entries. I referred to the customer/sales data available in our Fabric Lakehouse:</p>
<p>&nbsp;</p>
<img />
<p>&nbsp;</p>
<p>You can add more entries referring to the related data from Lakehouse. These 2 entries are enough for the time being for our demo purpose.</p>
<p><strong>Setting up Copilot Agent</strong></p>
<p>Now open your Copilot Studio and start creating an agent. Give it a name of your choice and select “GPT-5 Chat” as the model. Once created, in the Agents tab click on “Add an agent” and then “Connect to an external agent”. You can add both your Fabric Data Agent and Foundry Prompt Agent through this.</p>
<p>Next, open the Knowledge tab and click on “Add knowledge” and then on “SharePoint (Powered by Work IQ)”. Here you add your SharePoint list and add it to the agent.</p>
<p>At the end, In the instruction write the following. Change the name of your Data and Prompt agents and SharePoint knowledge source suitably:</p>
<p>“<em>You are an intelligent agent assisting customer service representatives of Adventure Works Inc. You have different sources to retrieve data. Give least priority to answers generated by the LLM model and give highest priorities to the data retrieved from these data sources. </em></p>
<p><em>To start with if the requirement is customer support, then ask for customer name, sales order id, and if they are calling due to an existing support request then support case id. Then use following sources to get data: </em></p>
<ol>
<li><em> Foundry IQ Agent - use this connected agent to answers questions on Adventure Works Inc. Retail Customer Support Representative Guide, Retail Customer Terms and Conditions, Retail Customer Payment, Purchase, Shipping &amp; Refund Information. </em></li>
<li><em> AWDataAgent - use this connected agent to retrieve sales data about orders by the customers, about sellers/employees, about products and product subcategories and categories. This is based on Ontology that defines the relationships among the entities. </em></li>
<li><em> Use the knowledge source Support_Data through SharePoint to fetch data about the support request/case/ticket raised by the customer previously. If the customer has previous support case open bring that info additionally once you get information about the customer. </em></li>
</ol>
<p><em>If given a Sales Order ID, or Customer Name, Customer ID and the question is not relevant to support case then use AWDataAgent connected agent. If it is specific to existing support request, then use SharePoint List knowledge source.</em>”</p>
<p>That’s it. Our demo is ready. Now test it with a series of relevant questions:</p>
<p><em>“I have to help a customer”.</em></p>
<p><em>“The Sales Order ID is 58970”.</em></p>
<p><em>“Is there any support case opened by this customer?”.</em></p>
<p><em>“Customer is asking the Half Finger Gloves are not up to the quality and she wants to return. But she used it. Can we do that?”.</em></p>
<p>That’s it. Your demo is ready for the show.</p>
</details>

### Building 3IQ Retail Assistant Demo – Part 2

- **Link**: [https://techcommunity.microsoft.com/t5/azure-architecture-blog/building-3iq-retail-assistant-demo-part-2/ba-p/4547231](https://techcommunity.microsoft.com/t5/azure-architecture-blog/building-3iq-retail-assistant-demo-part-2/ba-p/4547231)
- **Published**: 2026-09-04 02:24:04
- **Fetched**: 2026-09-04 10:36:48

<details class="entry-summary">
<summary>詳細を表示</summary>
<p>In part 1 while setting up the Azure environment, I informed the template puts everything under VNET and all the services are having only private endpoints. Which is great from the security point of view. We also spoke about creating a jumpbox as a Bastion host to work on those services. If you did it already – great, if not, we can bypass the situation by opening the public endpoint from Networking menu for each of these following services.&nbsp;</p>
<p><strong>Setting up Blob Storage Container </strong></p>
<p>Unlike structured data used for Foundry, we will use some unstructured data (pdf files) for Foundry and build knowledge source and knowledge base and will use those with our Foundry agent. To start with, I used 3 PDF files as listed below:</p>
<ul>
<li>Adventure Works Inc Retail Customer Support Representative Guide.pdf</li>
<li>Adventure Works Inc. – Retail Customer Terms and Conditions.pdf</li>
<li>Adventure Works Inc. – Retail Customer Payment, Purchase, Shipping &amp; Refund Information.pdf</li>
</ul>
<p>I used synthetic data for these PDF files. You can use Copilot, ChatGPT, Gemini, or Claude to generate the content.</p>
<p>Once done, we will create a Blob Container. There is a Storage Account created already by the template. You can use it to create the Blob Container. Now upload these 3 files there. You may have to add your account as a Storage Blob Data Contributor to upload the files if not already there.</p>
<p>We need to add few more permissions to this container. Add Storage Blob Data Reader access to:</p>
<ul>
<li>Foundry account's managed identity</li>
<li>Foundry Project's managed identity</li>
<li>Azure AI Search service's managed identity</li>
</ul>
<p><strong>Setting up Search </strong></p>
<p>A search service is already provisioned by the template. Use this to set up your knowledgebase and knowledgesource. Create the knowledgesource with similar set up:</p>
<p>&nbsp;</p>
<img />
<p>&nbsp;</p>
<p>Then create a knowledgebase using this knowledgesource and with the following description: “<em>Use this to answer questions related to Adventure Works Inc.'s retail customer policies, including the Support Representative Guide, Terms and Conditions, and Payment, Purchase, Shipping &amp; Refund information</em>”. I kept the Retrieval Reasoning Effect as Minimal and didn’t add any Chat completion model as such.</p>
<p><strong>Setting up Foundry Agent</strong></p>
<p>It’s time now to set up our Foundry Agent. Create a simple prompt agent and use any Chat completion model. It can be any LLM or SLM of your choice. This agent can be pro-code one using either Agent Service SDK or a hosted agent using MAF or LangGraph. But we would like to keep it simple for this demo.</p>
<p>For the Instructions I have written –</p>
<p>“<em>You are an intelligent agent to answer questions on Adventure Works Inc. Retail Customer Support Representative Guide, Retail Customer Terms and Conditions, Retail Customer Payment, Purchase, Shipping &amp; Refund Information.</em></p>
<p><em>Please answer from the knowledgebase only. If answer is not available within knowledgebase say not available politely</em>”.</p>
<p>And now add the knowledgebase you created within the search service. That’s pretty much it. Your Foundry Agent with IQ is ready and you can now ask a few complex questions to it like – “<em>Can customer get refund if the delivery is returned due to wrong address?</em>”, "<em>Can customer get refund if the shipping is delayed?</em>", “<em>Customer wants to return but she doesn't have the bill. Can she return the product?</em>” etc.</p>
<p>At last, make sure you turn your Foundry service public on Azure Portal by going to Resource Management &gt; Networking &gt; Firewall and Virtual Networks. This is required to publish the Foundry Agent to M365 Copilot:</p>
<p>&nbsp;</p>
<img />
<p>&nbsp;</p>
<p>As of today, you cannot publish the agent if it has a private endpoint. There are workarounds by creating the Bot service separately (the publish option does the magic silently) and exposing the Agent endpoint using APIM/App Gateway etc. I haven’t taken that route for this demo to make it simple. But here are some links just in case someone would like to explore:</p>
<p><a href="https://learn.microsoft.com/en-us/azure/foundry/agents/how-to/publish-copilot-virtual-network" target="_blank">Publish agents to Microsoft 365 and Teams by using the REST API - Microsoft Foundry | Microsoft Learn</a></p>
<p><a href="https://www.russrimmerman.com/blog/foundry-agents-teams-private-endpoint/" target="_blank">Publish Foundry Agents to Teams Behind a Private Endpoint · Russ Rimmerman</a></p>

<p><strong>Introduction</strong></p>
<p>Recently I received a request from one of our GSI partners to demonstrate them 4IQs on a retail industry scenario. Unfortunately, Web IQ is still not in public preview. Hence, I promised them to come back with an example later with Web IQ. But even with the remaining Fabric IQ, Foundry IQ and Work IQ, the issue is finding the right set of data and then build a story around it to demonstrate an agentic solution addressing some practical real-life scenario.</p>
<p>After doing some research with available data, I formulated a plan to prepare an assistant for customer reps to address incoming questions and requests from customers. This article describes how to build such an environment to demonstrate the capability of 3IQs together.</p>
<p>First, we need an Azure subscription with option to provision Fabric capacity, need Foundry, M365, and Copilot Studio access. Once you have those, let’s move to set up our environment.</p>
<p><strong>Environment Set Up</strong></p>
<p>I have limited time in hand. So, I went ahead with existing templates to implement Foundry and surrounding services on Azure. I used this Bicep template: <a href="https://github.com/microsoft-foundry/foundry-samples/tree/main/infrastructure/infrastructure-setup-bicep/16-private-network-standard-agent-apim-setup" target="_blank">foundry-samples/infrastructure/infrastructure-setup-bicep/16-private-network-standard-agent-apim-setup at main · </a><a href="https://github.com/microsoft-foundry/foundry-samples/tree/main/infrastructure/infrastructure-setup-bicep/16-private-network-standard-agent-apim-setup" target="_blank">microsoft</a><a href="https://github.com/microsoft-foundry/foundry-samples/tree/main/infrastructure/infrastructure-setup-bicep/16-private-network-standard-agent-apim-setup" target="_blank">-foundry/</a><a href="https://github.com/microsoft-foundry/foundry-samples/tree/main/infrastructure/infrastructure-setup-bicep/16-private-network-standard-agent-apim-setup" target="_blank">foundry-samples</a>. There are several other templates available on that page. You can choose any one of those based on your preference. This template puts all resources including Foundry behind private endpoints with no public internet access. You can add a jumpbox as a Bastion host to connect to all these services. Or time to time you can make those services public to complete your work.</p>
<p><strong>Setting up Fabric</strong></p>
<p>We will start with data layer which is Fabric. It is not provisioned yet. I provisioned a Fabric capacity with minimum size/SKU (F2) within the Resource Group generated by the Bicep template earlier. Fabric is an expensive service, especially the higher SKUs are. So, we need to be careful not spend too much and surpass our monthly Azure quota. Once provisioned, go to <a href="https://app.fabric.microsoft.com/" target="_blank">https://app.fabric.microsoft.com/</a> and create a Workspace using the same Fabric Capacity we provisioned earlier.</p>

But prior to that, let’s go to the Fabric capacity on Azure Portal and increase the size to a bigger SKU such as F64. We will load AdventureWorks sales data into the Lakehouse. There is a detail description here showing how to do it: <a href="https://learn.microsoft.com/en-us/fabric/graph/quickstart" target="_blank">Quickstart: Create Your First Graph in Microsoft Fabric - Microsoft Fabric | Microsoft Learn</a>.
