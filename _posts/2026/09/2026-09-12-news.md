### Azure App Service is now a trigger destination for Azure Managed Connectors

- **Link**: [https://techcommunity.microsoft.com/t5/apps-on-azure-blog/azure-app-service-is-now-a-trigger-destination-for-azure-managed/ba-p/4555785](https://techcommunity.microsoft.com/t5/apps-on-azure-blog/azure-app-service-is-now-a-trigger-destination-for-azure-managed/ba-p/4555785)
- **Published**: 2026-09-12 03:41:02
- **Fetched**: 2026-09-13 06:44:46

<details class="entry-summary">
<summary>詳細を表示</summary>
<p>Azure Managed Connectors, currently in public preview, now lets you choose <strong>Azure App Service as a trigger destination</strong>. Connector events can be delivered directly to applications running on App Service, including ASP.NET Core, Java, Node.js, and Python applications.</p>
<p>This is a new capability in the <strong>Managed Connectors public preview</strong>. It is not the announcement of a separate App Service preview.</p>
<h2>What's new</h2>
<p>When you create a trigger in the Managed Connectors portal, <strong>App Service</strong> now appears as a first-class destination alongside Azure Functions and the generic HTTP endpoint option.</p>
<p><img alt="App Service in the Azure Managed Connectors destination list" src="https://raw.githubusercontent.com/Azure-Samples/app-service-connectors-net-e2e-email-users-teams/main/docs/images/app-service-destination.png" /></p>
<p>After selecting an existing App Service app, you configure:</p>
<ul>
<li>The application route that receives the event. New triggers default to <code>POST /api/webhook</code>, and the route can be edited.</li>
<li>The Connector Namespace managed identity used to authenticate the callback.</li>
<li>The Microsoft Entra audience expected by the receiving application.</li>
</ul>
<p>Managed Connectors then records the selected App Service resource, route, managed identity, and audience as part of the trigger configuration. You no longer need to select the generic HTTP destination and manually assemble the App Service callback URL.</p>
<h2>What are managed connectors?</h2>
<p>Managed connectors provide a consistent way for applications to integrate with services such as Office 365, SharePoint, Teams, Dataverse, and Salesforce. A Connector Namespace manages connections and connector operations so developers do not need to build a separate OAuth flow and service-specific client for every integration.</p>
<p>Managed connectors support both directions:</p>
<ul>
<li><strong>Triggers</strong> deliver events to your application, such as a new Outlook email or a file added to SharePoint.</li>
<li><strong>Actions</strong> let your application call operations such as posting a Teams message, flagging an email, or creating a list item.</li>
</ul>
<p>The App Service destination makes the trigger side a first-class option for existing web applications and APIs.</p>
<h2>How it works</h2>
<ol>
<li>In the Managed Connectors portal, create a trigger and select <strong>App Service</strong> as its destination.</li>
<li>Select the web app, callback route, Connector Namespace managed identity, and Microsoft Entra audience.</li>
<li>When the source event occurs, Managed Connectors requests a token using the selected managed identity and sends the event to the App Service route.</li>
<li>App Service built-in authentication validates the token before the request reaches application code.</li>
<li>The application processes the event and can use Managed Connectors actions to continue the workflow.</li>
</ol>
<p>The callback is an ordinary authenticated HTTP request, so the application can use its normal framework, routing, dependency injection, logging, monitoring, and deployment practices.</p>
<h2>Configure receiving-app authentication</h2>
<p>The App Service destination configures the <strong>Managed Connectors side</strong> of the callback. The receiving application must still be configured to trust it.</p>
<p>The reference sample uses App Service built-in authentication, also known as Easy Auth, with:</p>
<ul>
<li>A Microsoft Entra application that identifies the receiving application and its audience.</li>
<li>A secretless federated credential configuration.</li>
<li>The Connector Namespace managed identity pinned as an allowed principal.</li>
<li>Authentication required for requests reaching the application.</li>
</ul>
<p>This configuration rejects unauthenticated requests and allows callbacks carrying the expected managed-identity token. The Managed Connectors trigger wizard does not currently create or update the App Service authentication configuration automatically.</p>
<h2>Try the end-to-end sample</h2>
<p>The <a href="https://github.com/Azure-Samples/app-service-connectors-net-e2e-email-users-teams" rel="noopener" target="_blank">Managed Connectors on Azure App Service email-triage sample</a> demonstrates a complete workflow:</p>
<ol>
<li>An Office 365 Outlook trigger delivers a new email to an ASP.NET Core application on App Service.</li>
<li>App Service built-in authentication validates the managed-identity callback.</li>
<li>The application classifies the message and enriches the sender through the Office 365 Users connector.</li>
<li>Important mail produces a Microsoft Teams triage card.</li>
<li>The application flags the source email in Outlook.</li>
</ol>
<p>The repository includes the application, Bicep infrastructure, App Service authentication configuration, Connector Namespace connections, and an Azure Developer CLI deployment flow.</p>
<p>We validated the complete workflow end to end: the authenticated callback reached <code>POST /api/webhook</code>, the application processed the event, a Teams card was posted, and the source Outlook message was flagged.</p>
<h2>Current limitations</h2>
<ul>
<li>The capability is configured through the <strong>Managed Connectors portal</strong>, not the App Service portal.</li>
<li>The wizard configures the Managed Connectors trigger but does not configure App Service built-in authentication on the selected web app.</li>
<li>The current sample authentication setup requires a Microsoft Entra application, audience configuration, federated credential, and allowed-principal configuration.</li>
<li>Depending on the application's Easy Auth configuration, authentication can apply to the whole application rather than only the connector callback route.</li>
<li>The reference sample validates one push-trigger scenario; it is not a compatibility statement for every connector and operation.</li>
</ul>
<h2>What's next</h2>
<p>The first-class App Service destination removes the generic callback URL step and provides an App Service-aware trigger experience in Azure Managed Connectors.</p>
<p>We are also exploring ways to simplify receiving-side authentication so applications can establish connector-scoped trust without manually assembling the App Service authentication configuration.</p>
<p>Try the <a href="https://github.com/Azure-Samples/app-service-connectors-net-e2e-email-users-teams" rel="noopener" target="_blank">reference sample</a> and share feedback on the connectors and App Service scenarios you want to use.</p>
