### What’s new in Azure Firewall: Recent innovations

- **Link**: [https://techcommunity.microsoft.com/t5/azure-networking-blog/what-s-new-in-azure-firewall-recent-innovations/ba-p/4552987](https://techcommunity.microsoft.com/t5/azure-networking-blog/what-s-new-in-azure-firewall-recent-innovations/ba-p/4552987)

- **Fetched**: 2026-09-05 15:23:49

<details class="entry-summary">

<p class="lia-align-left"><span>Organizations are modernizing their networks while managing a growing mix of applications, protocols, and security requirements. </span></p>
<p class="lia-align-left"><span>Recent Azure Firewall releases strengthen this journey with simpler traffic routing, expanded protocol support, more flexible application controls, improved health visibility, and higher intrusion-detection performance. This roundup highlights five recent capabilities now available in general availability or public preview.</span><span>&nbsp;</span></p>
<p class="lia-align-left"><strong><span>In this update:</span></strong><span><strong>&nbsp;</strong>Explicit proxy, IPv6 support, HTTP header insertion, auto-learn SNAT routes, and IDPS performance improvements.</span><span>&nbsp;</span></p>
<h3><span><span>Explicit&nbsp;</span><span>p</span><span>roxy is now generally available</span></span><span>&nbsp;</span></h3>
<p><span>Explicit&nbsp;proxy enables clients and applications to send HTTP and HTTPS traffic directly to Azure Firewall by configuring the&nbsp;firewall&nbsp;as their proxy. Instead of relying only on route-based traffic steering, organizations can use familiar proxy settings to centralize outbound web access through Azure Firewall.</span><span>&nbsp;</span></p>
<p><span>This release&nbsp;provides&nbsp;a simpler way to use Azure Firewall as a managed forward proxy. It can help teams&nbsp;consolidate&nbsp;web egress controls, support workloads that natively understand proxy configuration, and transition from traditional proxy appliances without introducing another infrastructure layer.</span><span>&nbsp;</span></p>
<ul>
<li><strong><span>Direct proxy configuration:</span></strong><span><strong>&nbsp;</strong>Configure supported clients and applications&nbsp;to use&nbsp;Azure Firewall for HTTP and HTTPS traffic.</span><span>&nbsp;</span></li>
</ul>
<ul>
<li><strong><span>Centralized web controls:</span></strong><span>&nbsp;Apply Azure Firewall policy and application rules to proxied traffic.</span><span>&nbsp;</span></li>
</ul>
<ul>
<li><strong><span>Operational simplicity:</span></strong><span>&nbsp;Use a managed Azure service instead of deploying and&nbsp;maintaining&nbsp;separate proxy infrastructure.</span><span>&nbsp;</span></li>
</ul>
<ul>
<li><strong><span>Migration flexibility:</span></strong><span><strong>&nbsp;</strong>Support environments that already use proxy-aware applications or proxy auto-configuration workflows.</span><span>&nbsp;</span></li>
</ul>
<p>&nbsp;</p>
<img />
<p><span><strong>For more details, visit</strong> -&nbsp;</span><a href="https://learn.microsoft.com/en-us/azure/firewall/explicit-proxy?tabs=portal" rel="noopener" target="_blank"><span><span>Azure Firewall explicit proxy | Microsoft Learn</span></span></a><span>&nbsp;</span></p>
<h3><span><span>IPv6 support is now in public preview</span></span><span>&nbsp;</span></h3>
<p><span>As address requirements grow and organizations adopt dual-stack architectures, IPv6 support is becoming an important part of cloud network design. Azure Firewall IPv6 support, now in public preview, extends centralized traffic filtering to IPv6 scenarios and helps customers protect applications and networks as they introduce IPv6 connectivity.</span><span>&nbsp;</span></p>
<p><span>With this preview, teams can evolve IPv4-only environments toward dual-stack networking while continuing to use Azure Firewall as a central enforcement point.&nbsp;This reduces the need to&nbsp;maintain&nbsp;separate security architectures for IPv4 and IPv6 traffic and provides a more consistent policy and operational model.</span><span>&nbsp;</span></p>
<ul>
<li><strong><span>Secure IPv6 traffic across hybrid environments</span><span>:</span></strong><span>&nbsp;</span><span>Filter east-west and hybrid IPv6 traffic across Azure and on-premises networks.</span><span>&nbsp;</span></li>
</ul>
<ul>
<li><span><strong>Works seamlessly with IPv6-enabled Azure services:</strong>&nbsp;</span><span>Integrate Azure Firewall into end-to-end IPv6 architectures alongside services like ExpressRoute and Virtual Network.</span><span>&nbsp;</span></li>
</ul>
<ul>
<li><span><strong>Prepare for the future of networking:</strong>&nbsp;</span><span>Build and secure dual-stack environments today while accelerating your IPv6 adoption journey.</span><span>&nbsp;</span></li>
</ul>
<p><span>For more details,&nbsp;visit -</span><a href="https://learn.microsoft.com/en-us/azure/firewall/deploy-dual-stack-firewall?tabs=portal" rel="noopener" target="_blank"><span><span>Deploy Azure Firewall in dual stack mode (preview) | Microsoft Learn</span></span></a></p>
<h3><span><span>HTTP </span><span>h</span><span>eader&nbsp;</span><span>i</span><span>nsertion is now generally available</span></span><span>&nbsp;</span></h3>
<p><span>HTTP&nbsp;header&nbsp;insertion enables Azure Firewall to add configured headers to HTTP requests that match application rules. This gives security and network teams an&nbsp;additional&nbsp;policy control for communicating trusted context to downstream services without requiring every client or application to add the header itself.</span><span>&nbsp;</span></p>
<p><span>The capability can support scenarios where applications use headers to enforce organization-specific access requirements,&nbsp;identify&nbsp;traffic handled by a trusted network path, or apply downstream controls. Because configuration is centralized in Azure Firewall&nbsp;policy, teams can apply the behavior consistently across matching traffic and reduce application-side changes.</span><span>&nbsp;</span></p>
<ul>
<li><span><strong>Tenant restriction enforcement:</strong>&nbsp;</span><span>Organizations can inject tenant restriction headers into traffic destined for Microsoft Entra ID, helping prevent users from authenticating unauthorized tenants and strengthening identity governance controls.</span><span>&nbsp;</span></li>
</ul>
<ul>
<li><strong><span><span>Secure egress for AVD and enterprise workloads:&nbsp;</span></span></strong><span><span>Support AVD, VDI, and enterprise egress scenarios where organizations need web traffic to carry approved tenant or context headers.<br /><br /></span></span></li>
<li><strong><span>Security and Compliance Enforcement: </span></strong><span style="color: rgb(30, 30, 30);"><span>Administrators can add organization-specific headers to web traffic to support security policies, compliance requirements, and backend&nbsp;</span><span>validation</span><span>&nbsp;workflows. This helps ensure that only approved applications, tenants, or services are accessed through corporate environments.</span></span><span style="color: rgb(30, 30, 30);">&nbsp;</span></li>
</ul>
<ul>
<li><span><span><strong>Operational Efficiency:</strong>&nbsp;</span></span><span><span>Customers no longer need dedicated proxy devices solely for HTTP header injection. Azure Firewall can now perform header insertion natively as part of the application rule, reducing operational complexity and infrastructure costs.</span></span><span>&nbsp;</span></li>
</ul>
<p>&nbsp;</p>

<p><span><strong>For more details,&nbsp;visit </strong>-&nbsp;</span><a href="https://learn.microsoft.com/en-us/azure/firewall/configure-http-header-insertion?tabs=portal" rel="noopener" target="_blank"><span><span>Azure Firewall HTTP Header Insertion Configuration | Microsoft Learn</span></span></a></p>
<h3><span><span>Auto-</span><span>l</span><span>earn SNAT&nbsp;</span><span>r</span><span>outes&nbsp;</span><span>is</span><span>&nbsp;now generally available</span></span><span>&nbsp;</span></h3>
<p><span>Source network address translation behavior depends on whether Azure Firewall treats a destination as private or public.&nbsp;In complex enterprise and hybrid networks, manually&nbsp;maintaining&nbsp;the private address ranges that should not be source-NATed can become time-consuming and error-prone as the environment changes.</span><span>&nbsp;</span></p>
<p><span>Auto-learn SNAT&nbsp;routes&nbsp;simplifies&nbsp;this process by dynamically learning relevant routes through Azure Route Server and using them to update the firewall’s private IP range&nbsp;configuration. This helps Azure Firewall preserve original source addresses for traffic destined to&nbsp;learned&nbsp;private networks while reducing ongoing configuration maintenance.</span><span>&nbsp;</span></p>
<ul>
<li><strong><span>Reduce manual SNAT management</span> : </strong><span>Automatically learn private and registered routes through Azure Route Server,&nbsp;eliminating&nbsp;the need to manually&nbsp;maintain&nbsp;large No-SNAT prefix lists.</span><span>&nbsp;</span></li>
</ul>
<ul>
<li><strong><span>Preserve source IPs across hybrid networks</span> : </strong><span>Automatically apply learned routes as No-SNAT destinations, helping&nbsp;maintain&nbsp;source IP visibility and predictable routing for internal traffic.</span><span>&nbsp;</span></li>
</ul>
<p><strong><span>For more details, visit-&nbsp;</span></strong><a href="https://learn.microsoft.com/en-us/azure/firewall/snat-private-range" rel="noopener" target="_blank"><span><span>Azure Firewall SNAT private IP address ranges | Microsoft Learn</span></span></a><span>&nbsp;</span></p>
<h3><span><span>IDPS performance improvements are now generally available</span></span><span>&nbsp;</span></h3>
<p><span>Azure Firewall Premium includes signature-based intrusion detection and prevention to&nbsp;identify&nbsp;and block malicious network activity. The latest IDPS performance improvements&nbsp;increase the amount of protected traffic that Azure Firewall Premium can process, helping organizations apply advanced inspection to demanding production workloads.</span><span>&nbsp;</span></p>
<p><span>Azure Firewall Premium now supports up to&nbsp;</span><span>22 Gbps</span><span>&nbsp;with TLS inspection and IDPS in Deny mode, and up to&nbsp;</span><span>600 Mbps</span><span>&nbsp;for a single TCP connection when IDPS is enabled in Alert or Deny mode. Actual performance depends on traffic characteristics, rule configuration, enabled features, and deployment conditions.</span><span>&nbsp;</span></p>
<ul>
<li><strong><span>Higher aggregate throughput:</span></strong><span><strong>&nbsp;</strong>Protect larger traffic volumes while using advanced inspection capabilities.</span><span>&nbsp;</span></li>
</ul>
<ul>
<li><strong><span>Improved single-flow performance:</span></strong><span>&nbsp;Better support applications that rely on high-throughput TCP connections.</span><span>&nbsp;</span></li>
</ul>
<ul>
<li><strong><span>Strong prevention posture:</span></strong><span>&nbsp;Use IDPS Deny mode to actively&nbsp;block matching&nbsp;malicious traffic.</span><span>&nbsp;</span></li>
</ul>
<ul>
<li><strong><span>Premium-scale security:</span></strong><span> Apply TLS inspection and IDPS to more bandwidth-intensive enterprise workloads</span></li>
</ul>
<p><strong><span>For more details, visit -</span></strong><span>&nbsp;</span><a href="https://learn.microsoft.com/en-us/azure/firewall/firewall-performance" rel="noopener" target="_blank"><span><span>Azure Firewall performance | Microsoft Learn</span></span></a><span>&nbsp;</span></p>
<h2><span><span>Building an advanced, more capable cloud </span><span>firewall</span></span><span>&nbsp;</span></h2>
<p><span>Together, these releases expand how Azure Firewall can protect modern networks. Explicit proxy and HTTP header insertion provide more flexible application-layer controls; IPv6 support helps customers evolve toward dual-stack architectures; Auto-learn SNAT routes reduces operational overhead in dynamic and hybrid environments;&nbsp; and IDPS performance improvements extend advanced threat prevention to higher-throughput workloads.</span><span>&nbsp;</span></p>
<p><span>Explore these capabilities in Azure Firewall and review the applicable Azure documentation for configuration requirements, supported scenarios, regional availability, and preview terms before enabling them in production environments.</span><span>&nbsp;</span></p>
