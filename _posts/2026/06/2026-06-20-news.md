<h3>Purpose of the blog&nbsp;</h3>
<p>This blog outlines the key upcoming changes to Azure Firewall explicit proxy and provides detailed migration guidance for customers using PAC file–based configurations. It also covers the supported deployment options for enabling explicit proxy after the changes are released, including the Azure portal, PowerShell, and Azure CLI.</p>
<h3>Who is this article for?</h3>
<p>This article is intended for customers currently using Azure Firewall explicit proxy in preview. If you use PAC file–based proxy configuration, follow the steps below to configure the new PAC file SAS URL retrieval method, which will become the standard approach going forward.</p>
<h3>Azure Firewall explicit proxy</h3>
<p>Azure Firewall operates in a transparent proxy mode by default. In this mode, you use a user-defined route (UDR) configuration to send traffic to the firewall. The firewall intercepts that traffic inline and passes it to the destination.</p>
<p>When you set up explicit proxy on the outbound path, you can configure a proxy setting on the sending application (such as a web browser) with Azure Firewall configured as the proxy. As a result, traffic from the sending application goes to the firewall's private IP address and therefore egresses directly from the firewall without using a UDR.</p>
<p>The Azure Firewall explicit proxy feature is in Preview at the time this article was published.</p>
<h3>Upcoming changes to the explicit proxy feature in Azure Firewall</h3>
<ul>
<li>PAC (Proxy Auto-Configuration) file size is now limited to <strong>256 KB</strong>.</li>
<li>Support HTTP and HTTPS traffic over a <strong>single HTTP proxy port.</strong></li>
<li>Removal of the previous dual-port configuration requirement (explicit proxy v1).</li>
<li>Ability to enable explicit proxy directly using Firewall Policy creation in the Azure portal.</li>
<li>Following general availability (GA), explicit proxy will require both a <strong>PAC file SAS URL and Managed Identity (MSI)</strong>, along with the appropriate role assignments to meet Microsoft security standards.</li>
</ul>
<h6>Follow the steps below to&nbsp;<span>migrate to the new PAC file retrieval model that uses customer-managed Azure Storage and Managed Identity authentication.</span></h6>
<h3>Step 1: Create a PAC File SAS URL</h3>
<ul>
<li>Create an Azure Storage container by following the steps in <a href="https://learn.microsoft.com/en-us/azure/storage/blobs/blob-containers-portal" rel="noopener" target="_blank">Manage blob containers using the Azure portal - Azure Storage | Microsoft Learn</a>. <strong>Note: Use a subscription in which required permissions to add roles exist.</strong></li>
<li>Upload the PAC file to the storage container.</li>
</ul>
<img />
<ul>
<li>Select the uploaded file and copy the file URL. Example URL: "<a href="https://eproxypstestresources.blob.core.windows.net/explicitproxycontainer/proxy.pac" rel="noopener" target="_blank">https://eproxypstestresources.blob.core.windows.net/explicitproxycontainer/proxy.pac</a>"</li>
</ul>
<img />
<h3>Step 2: Create a Managed Identity and assign required roles</h3>
<ul>
<li>Navigate to <em>Managed Identity</em> blade and create a Managed Identity. See <a href="https://learn.microsoft.com/en-us/entra/identity/managed-identities-azure-resources/manage-user-assigned-managed-identities-azure-portal" rel="noopener" target="_blank">Manage user-assigned managed identities using the Azure portal - Managed identities for Azure resources | Microsoft Learn</a> for more details.</li>
<li>Go to the storage account resource created in the previous step and navigate to <em>Access Control (IAM)</em>. Select <em>Add</em> to add the role assignment.</li>
<li>Go to the <em>Add role assignment</em> page and search for <em>Storage Blob Data Contributor</em> and <em>Storage Blob Data Reader</em>, then select both.</li>
</ul>
<img />
<ul>
<li>Go to&nbsp;<em>Members</em> → <em>Managed Identity</em> and select the identity created earlier. Review the changes and click <em>Assign</em> in <em>Review + Assign </em>blade.</li>
</ul>
<img />
<p>&nbsp;</p>
<ul>
<li>Verify that your changes are reflected under&nbsp;<em>Role Assignments</em> by searching for the managed identity.&nbsp;<strong>Note: Make sure that the Managed Identity created has prefix "PacFileMSI-".</strong></li>
</ul>
<img />
<p>&nbsp;</p>
<h3>Configuration using portal, PowerShell and Azure CLI</h3>
<h4>Portal configuration</h4>
<p>After obtaining the PAC file SAS URL and Managed Identity, enable the PAC file in the explicit proxy configuration by:</p>
<ul>
<li>providing the PAC file SAS URL, and</li>
<li>selecting the Managed Identity created in the previous steps.</li>
</ul>
<img />
<h4>PowerShell configuration</h4>
<p>To securely use explicit proxy, customers must provide:</p>
<ul>
<li>the PAC file SAS URL, and</li>
<li>a Managed Identity with the required permissions to access the PAC file from the customer-managed Blob Storage account.</li>
</ul>
<ol>
<li>Create Firewall Policy with explicit proxy settings:$exProxy = New-AzFirewallPolicyExplicitProxy ` -EnableExplicitProxy ` -HttpPort 100 ` -EnablePacFile ` -PacFilePort 130 ` -PacFile "https://sampleurlfortesting.blob.core.windows.net/container/proxy.pac"
<p>&nbsp;</p>
</li>
<li>
<pre>Update Firewall Policy with explicit proxy configuration:</pre>
New-AzFirewallPolicy ` -Name "fp1" ` -ResourceGroupName "TestRg" ` -ExplicitProxy $exProxy ` -UserAssignedIdentityId "/subscriptions/e7eb2257-46e4-4826-94df-153853fea38f/resourcegroups/testrg/providers/Microsoft.ManagedIdentity/userAssignedIdentities/PacFileMSI-eproxyidentity"</li>
</ol>
<h4>Azure CLI configuration</h4>
<ol>
<li>Create Firewall Policy with explicit proxy settings:az network firewall policy create -g "testrg" -n "testfwpolicy" --sku Premium --explicit-proxy enable-explicit-proxy=true http-port=9001 enable-pac-file=true pac-file-port=122 pac-file="https://eproxypstestresources.blob.core.windows.net/explicitproxycontainer/proxy.pac" --identity "Identity_ID"
<p>&nbsp;</p>
</li>
<li>Update Firewall Policy with Explicit Proxy Configuration:az network firewall policy update -g "testrg" -n "testfwpolicy" --explicit-proxy enable-explicit-proxy=true http-port=9001 enable-pac-file=true pac-file-port=124 pac-file="https://eproxypstestresources.blob.core.windows.net/explicitproxycontainer/proxy.pac" --identity "Identity_ID"</li>
</ol>
