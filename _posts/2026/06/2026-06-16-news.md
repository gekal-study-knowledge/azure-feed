# Azure Updates - 2026-06-16

## Azure Networking Blog

### Network security perimeter for Azure Service Bus & also now available in Azure Gov. Regions

- **Link**: [https://techcommunity.microsoft.com/t5/azure-networking-blog/network-security-perimeter-for-azure-service-bus-also-now/ba-p/4526413](https://techcommunity.microsoft.com/t5/azure-networking-blog/network-security-perimeter-for-azure-service-bus-also-now/ba-p/4526413)
- **Published**: 2026-06-16 19:56:27
- **Fetched**: 2026-08-27 21:13:49

<h3>TL; DR</h3>
<p>Network security perimeter support for Azure Service Bus is now <strong>Generally Available</strong>. With this, you can now place your Service Bus namespace inside a central security boundary and apply perimeter-based governance for inbound/outbound network access—while keeping key PaaS-to-PaaS scenarios secure and auditable.</p>
<h1><strong>Introduction</strong></h1>
<p>We’re excited to announce that <strong>network security perimeter support for Azure Service Bus is now Generally Available (GA)</strong>.</p>
<p>This milestone brings one of Azure’s most widely used messaging services into the network security perimeter ecosystem, enabling customers to define a centralized security boundary across messaging and data services.</p>
<p>Alongside this, we are also expanding network security perimeter’s reach — network security perimeter is now available in Azure Government regions, including:</p>
<ul>
<li>Texas</li>
<li>Arizona</li>
<li>Virginia</li>
<li>DoD East</li>
<li>DoD Central</li>
</ul>
<p>This ensures that customers operating in regulated, sovereign, and mission-critical environments can adopt network security perimeter while meeting their compliance and regional requirements.</p>
<h1><strong>Why this matters?</strong></h1>
<p>Modern applications rely heavily on messaging layers like Service Bus. These systems often connect microservices, data platforms, key management systems and external integrations. As architectures scale, managing network access individually becomes complex and error prone.</p>
<p>Network security perimeter changes this by introducing a perimeter-based access model, where:</p>
<ul>
<li>Communication is restricted by default</li>
<li>Access must be explicitly allowed</li>
<li>Governance is applied consistently across services</li>
</ul>
<p>With Service Bus now onboarded and network security perimeter extending into Azure Gov regions, customers can apply this model across both commercial and sovereign environments.</p>
<h1><strong>What you can do with Service Bus + network security perimeter</strong></h1>
<h2>Confine communication within a security boundary</h2>
<p>Service Bus namespaces communicate only with resources inside the perimeter by default—blocking unintended access.</p>
<h2>Secure PaaS-to-PaaS communication</h2>
<p>Enable secure interactions between Service Bus, Azure Key Vault (for CMK scenarios) and other network security perimeter-enabled services (<a href="https://learn.microsoft.com/en-us/azure/private-link/network-security-perimeter-concepts#onboarded-private-link-resources" rel="noopener" target="_blank">What is a network security perimeter? - Azure Private Link | Microsoft Learn</a>)</p>
<h2>Define explicit access controls</h2>
<ul>
<li>Inbound rules → IP ranges and subscriptions</li>
<li>Outbound rules → FQDN-based filtering</li>
</ul>
<h2>Enable audit and compliance visibility</h2>
<p>Diagnostic logs capture all access attempts, supporting compliance and investigation workflows.</p>
<h2>Use Private Link seamlessly</h2>
<p>Private endpoint traffic continues to work without additional configuration inside the perimeter.</p>
<h1><strong>Azure Government Availability</strong></h1>
<p>With this update, network security perimeter is now available in key <strong>Azure Government regions (Texas Arizona Virginia DoD East DoD Central)</strong>, enabling:</p>
<h2>Consistent security across clouds</h2>
<p>Apply the same network security perimeter model across public Azure regions and Azure Government environments.</p>
<h2>Support for regulated workloads</h2>
<p>Customers in federal, defence, and highly regulated industries can now:</p>
<ul>
<li>Enforce perimeter-based governance</li>
<li>Reduce exposure risks</li>
<li>Meet compliance requirements</li>
</ul>
<h2>Enable secure cross-service patterns in Gov clouds</h2>
<p>Azure Government boundaries now support scenarios like:</p>
<ul>
<li>CMK with Key Vault</li>
<li>Service-to-service messaging</li>
<li>Controlled external access</li>
</ul>
<p>More details of onboarded PaaS services are detailed in <a href="https://learn.microsoft.com/en-us/azure/private-link/network-security-perimeter-concepts#onboarded-private-link-resources" rel="noopener" target="_blank">What is a network security perimeter? - Azure Private Link | Microsoft Learn</a></p>
<h1><strong>What’s next</strong></h1>
<p>Service Bus GA further strengthens network security perimeter’s growing coverage across Azure PaaS services. We will continue to:</p>
<ul>
<li>Expand PaaS service onboarding</li>
<li>Improve access rule capabilities (e.g. Service tag-based access, identity-based access)</li>
