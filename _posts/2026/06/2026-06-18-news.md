### ICMP Support for Azure StandardV2 NAT Gateway

- **Link**: [https://techcommunity.microsoft.com/t5/azure-networking-blog/icmp-support-for-azure-standardv2-nat-gateway/ba-p/4528374](https://techcommunity.microsoft.com/t5/azure-networking-blog/icmp-support-for-azure-standardv2-nat-gateway/ba-p/4528374)
- **Published**: 2026-06-18 02:44:22
- **Fetched**: 2026-08-27 21:13:49

<details class="entry-summary">
<summary>詳細を表示</summary>
<p>Our customers, across all industries, depend on consistent outbound connectivity and observability to operate and troubleshoot their cloud workloads at scale. As Azure environments grow in size and complexity, teams increasingly rely on standard network diagnostic tools such as ping to quickly validate reachability and identify connectivity issues.</p>
<p>When customers route outbound traffic through Azure NAT Gateway, they benefit from centralized and scalable outbound connectivity designed to prevent SNAT port exhaustion, while simplifying management by removing the need for per‑resource public IPs. Historically, outbound connectivity through Azure NAT Gateway supported TCP and UDP traffic only for Azure workloads.</p>
<p><span>We are pleased to announce that Azure StandardV2 NAT Gateway now supports outbound ping through ICMP Echo Request and Echo Reply traffic. Workloads that rely on NAT Gateway for internet egress can now use ping to validate reachability, improving operational visibility and simplifying network troubleshooting while preserving the scalability and resiliency characteristics of NAT Gateway.</span><span>&nbsp;</span></p>
<h4><span><span><span>What’s now supported?</span></span></span></h4>
<p><span>Azure StandardV2 NAT Gateway supports outbound ICMP Echo Request and Echo Reply traffic (ping) for IPv4 and IPv6. Other ICMP message types are not currently supported.</span><span>&nbsp;</span></p>
<p><span>With this update, ICMP traffic sent from workloads behind a NAT Gateway can be translated to a public IP address and reliably receive responses from external endpoints. This brings ICMP behavior in line with existing TCP and UDP outbound flows, enabling consistent network diagnostics across all common transport types.</span><span>&nbsp;</span></p>
<p><span>This capability is available automatically when workloads egress through a&nbsp;StandardV2 NAT Gateway - no additional configuration or rule changes are required.</span><span>&nbsp;</span></p>
<h4><span><span>Scenarios enabled by ICMP support</span></span><span>&nbsp;</span></h4>
<p><span><span>Support for ICMP through&nbsp;</span><span>StandardV2 </span><span>NAT Gateway</span><span>&nbsp;unlocks several common operational scenarios:</span></span><span>&nbsp;</span></p>
<ul>
<li><strong><span>Basic reachability testing&nbsp;</span></strong><span>– Operators can use ping from virtual machines, VM scale sets, or AKS nodes behind NAT Gateway to verify outbound connectivity to internet endpoints.</span><span>&nbsp;</span></li>
<li><strong><span>Health validation and troubleshooting</span></strong><span> –</span>&nbsp;<span>Teams can perform quick checks during incident triage without deploying jump hosts, public IPs per VM, or temporary firewall exceptions.</span></li>
</ul>
<p><span><span>These scenarios are especially valuable in large</span>‑<span>scale environments where workloads rely on centralized outbound connectivity via NAT Gateway.</span>&nbsp;</span></p>
<h4><span><span>How ICMP works through </span><span>StandardV2 </span><span>NAT Gateway</span></span><span>&nbsp;</span></h4>
<p><span>Unlike TCP or UDP, ICMP does not use ports to differentiate flows. Instead, ICMP messages include an identifier field, which is used by diagnostic tools to correlate requests and responses.</span><span>&nbsp;</span></p>
<p><span>A common troubleshooting scenario is when workloads deployed behind an Azure&nbsp;StandardV2 NAT Gateway&nbsp;are unable to reach external endpoints. Since these workloads typically do not have public IP addresses, it can be difficult to quickly determine whether the issue is related to basic network reachability or higher-layer configuration. In such cases, ICMP</span>‑<span>based diagnostics such as ping can be used to validate outbound connectivity and help isolate the source of the issue.</span><span>&nbsp;</span></p>
<p><strong><span>When a workload sends an outbound ICMP packet through a NAT Gateway:</span><span>&nbsp;</span></strong></p>
<ol>
<li><span>NAT Gateway translates the source private IP to one of its associated public IP addresses.</span></li>
<li>The platform tracks the ICMP flow using the ICMP identifier and other packet attributes.</li>
<li>Return ICMP responses from the external destination are matched to the originating flow.</li>
<li>The response is translated back to the original private IP and delivered to the workload.</li>
</ol>
<img />Flow chart showing handling of outbound ICMP Echo Request and Echo Reply traffic through Azure NAT Gateway
<p class="lia-clear-both"><span>This stateful handling allows replies to be routed correctly even when multiple workloads are sending ICMP traffic concurrently through the same NAT Gateway.</span><span>&nbsp;</span></p>
<h4 class="lia-clear-both"><span><span><span>Using ICMP for </span><span>end-to-end</span><span> outbound troubleshooting</span></span></span></h4>
<p class="lia-clear-both"><span>To validate outbound connectivity using ICMP from workloads deployed behind StandardV2 NAT Gateway:</span><span>&nbsp;</span></p>
<ol>
<li><span>Go to your virtual network in the Azure portal and select the subnet hosting your workload.</span></li>
<li><span>Verify that a StandardV2 NAT Gateway is associated with the subnet.</span><br />The workload does not require a public IP address.</li>
<li>Connect to the workload (for example, a virtual machine) running in the subnet.</li>
<li>Run an ICMP ping to an external destination to validate outbound reachability.<br /><img />
<p>Successful ping from a workload behind an Azure StandardV2 NAT Gateway demonstrating outbound connectivity and ICMP Echo reply.</p>
</li>
<li><span>Review the results.</span>&nbsp;<br /><span> Successful ICMP echo replies confirm that outbound connectivity through&nbsp;StandardV2 NAT Gateway&nbsp;is functioning and that ICMP traffic is translated and returned correctly</span><span>&nbsp;</span></li>
</ol>
<h4><span><span><span>Summary</span></span><span>&nbsp;</span></span></h4>
<p><span>With ICMP Echo support, Azure StandardV2 NAT Gateway provides a more complete outbound networking experience by enabling essential diagnostic tools to function reliably through NAT. Customers can validate reachability, perform basic troubleshooting, and diagnose connectivity issues while continuing to benefit from the simplicity and scale of centralized outbound connectivity.</span><span>&nbsp;</span></p>
